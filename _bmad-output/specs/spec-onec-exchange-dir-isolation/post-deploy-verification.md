# Проверка после выката на прод

Компаньон к `SPEC.md`. Выполняется через сутки после выката — окно замера подобрано под суточный объём 1 509 сессий обмена.

## Порядок выката

Деплой ручной, CI-шаг `Deploy to Production` всегда skipped.

1. `git fetch origin main; git reset --hard origin/main` (на проде **не** `git pull`).
2. Пересборка: импорт живёт в воркере, поэтому `celery` и `celery-beat` пересобираются **вместе** с `backend`.
3. Обязательный `docker compose restart nginx` после пересборки backend — иначе nginx держит старый IP upstream и весь внешний API вместе с обменом 1С падает в 502.
4. Миграции, если появятся, применяются вручную.

## 1. Падения «файл не найден» должны исчезнуть

```sql
SELECT count(*) FILTER (WHERE error_message LIKE '%не найден в каталоге обмена%') AS not_found,
       count(*) FILTER (WHERE status = 'failed') AS failed
FROM import_sessions
WHERE created_at > now() - interval '24 hours';
```

Приёмка: `not_found = 0`. База сравнения — 85 за 7 дней, все после ожидания лока.

## 2. Ожидание лока может остаться, падения после него — нет

```sql
SELECT count(*) FROM import_sessions
WHERE status = 'failed' AND report LIKE '%Каталог обмена занят%'
  AND created_at > now() - interval '24 hours';
```

Приёмка: `0`. Само сообщение об ожидании лока в отчётах успешных сессий регрессом **не** считается — очередь остаётся легитимной.

## 3. Каталоги не копятся

```bash
ls /home/freesport/freesport/data/prod/onec_private/1c_temp | wc -l
ls /home/freesport/freesport/data/prod/onec_private/1c_import | wc -l
```

Приёмка: после завершения обмена число папок возвращается к исходному и не растёт от обмена к обмену.

База сравнения — снимок счётчика, снятый **после ручной зачистки исторического мусора**, которую Alex выполняет сам вне этой работы. Число 32 276 (28.08.2026) — накопленное прошлое, не цель для автоматики. Практически: снять счётчик сразу после зачистки, повторить через сутки живого обмена, сравнить.

Отдельно проверяется порог 24 часа: каталог сессии, чей воркер упал, должен исчезнуть не позже суток.

## 4. Контрольная полная выгрузка номенклатуры

Запускается из 1С вручную. Приёмка:

- 20 сегментов `goods`, все `COMPLETED`;
- сумма `products_updated` равна числу товаров в каталоге;
- сумма обработанных сегментов за выгрузку равна числу присланных файлов — ни один сегмент не остался непрочитанным.

## 5. Изображения (CAP-2 на живых данных)

После контрольной выгрузки проверить, что товары, чьи картинки приехали отдельным `sessid`, получили изображения: XML лежал в сессионном каталоге, файл — в общем `import_files`.

## Что считать откатом

Появление хотя бы одного сегмента, не прочитанного никем (расхождение п. 4), — сигнал более серьёзный, чем прежние падения: до правки данные обычно доезжали чужим прогоном, после изоляции такого «спасателя» больше нет.
