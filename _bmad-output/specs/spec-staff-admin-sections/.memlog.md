- (direction) Источник — разговор с Alex 08.10.2026: нужны отдельные разделы админки для менеджеров (клиенты, валидация, блокировка) и маркетинга (баннеры, новости, блог, метки товаров) без служебной информации; затем добавлен руководитель.
- (decision) Три роли сотрудников: Менеджер, Маркетинг, Руководитель. Основная /admin/ остаётся только суперпользователю.
- (decision) Менеджеру даются заказы своих клиентов (Alex 08.10.2026).
- (decision) Менеджер может сбрасывать пароль клиентам своего региона, не сотрудникам (Alex 08.10.2026).
- (decision) Статические страницы маркетингу не даются — там юридические тексты (Alex 08.10.2026).
- (decision) Маркетинг видит только количество подписчиков, без списка и экспорта (Alex 08.10.2026).
- (decision) Менеджер видит только свой регион; чужого клиента — только через руководителя, даже на чтение (Alex 08.10.2026).
- (decision) Схема регионов: правило региона (страна или 2 цифры ИНН) указывает на учётную запись менеджера; у клиента поле «Ответственный менеджер», заполняется правилом, ручное назначение руководителя пересчёт не затирает (Alex 08.10.2026).
- (decision) Все регионы распределены между менеджерами; отдельной очереди «Без менеджера» нет — резервное правило указывает на руководителя, на странице регионов подсказка о нераспределённых кодах (Alex 08.10.2026).
- (decision) Настройки бонусной программы — руководителю (Alex 08.10.2026).
- (decision) Сверка ответственного менеджера с 1С отложена на следующий этап (Alex 08.10.2026).
- (capability) CAP-1 Роли сотрудников и изоляция: три группы, вход только в свои разделы, без доступа к /admin/, обмену 1С, запуску импорта, API мониторинга.
- (capability) CAP-2 Регионы и ответственный менеджер: таблица регион→менеджер, автоназначение, ручная правка, пересчёт существующих, письма о регистрации по той же таблице.
- (capability) CAP-3 Раздел менеджера: клиенты и заказы своего региона, верификация, блокировка/разблокировка, сброс пароля, привязка к 1С, счётчики.
- (capability) CAP-4 Раздел маркетинга: баннеры, новости, блог, рубрики, метки и скидка товаров, бренды, категории на главной, число подписчиков.
- (capability) CAP-5 Раздел руководителя: оба раздела без фильтра, сотрудники, регионы, переназначение, сводка, получатели уведомлений, настройки бонусов.
- (capability) CAP-6 Журнал действий сотрудников: читаемая лента критичных действий с фильтром по сотруднику.
- (constraint) is_staff сегодня открывает обмен 1С (Is1CExchangeUser), запуск импорта (staff_member_required), DRF IsAdminUser-метрики и include_inactive каталога — роли сотрудников не должны это наследовать.
- (constraint) В текущем UserAdmin любой с change_user правит is_superuser/is_staff/groups — эскалация до суперпользователя.
- (constraint) Права Django — уровень модели; скрыть поля 1С/служебные в карточке можно только отдельными урезанными представлениями.
- (constraint) Описание товара перезаписывает импорт 1С (variant_import.py:1178) — маркетингу его не давать.
- (constraint) Роль связанного с 1С клиента перезаписывает импорт (processor.py:618) по виду цен соглашения.
- (constraint) Смена статуса заказа: статус перезаписывает импорт 1С (order_status_import.py:755/899), переход в accrual_status (delivered) начисляет бонусы тренеру сигналом post_save.
- (constraint) Гостевые заказы без учётной записи возможны (Order.user null) — у них нет ответственного менеджера.
- (question) Менеджер меняет статус заказа или статус только из 1С? Ручной delivered начисляет бонусы, а 1С перезапишет статус.
- (question) Роль клиента в разделе менеджера: только при верификации и только чтение для связанных с 1С?
- (question) Один ответственный менеджер на регион или несколько; если несколько — кто ответственный у клиента?
- (question) Кто ведёт гостевые заказы без учётной записи — руководитель?
- (assumption) Каждый раздел — отдельный вход (/manager/, /marketing/), руководитель видит оба и свой; сотрудникам нужен is_staff=True для входа в Django-админку.
- (assumption) Названия регионов — статический справочник кодов 01–99 по первым цифрам ИНН, включая 90–95 и 99 (крупнейшие налогоплательщики).
- (assumption) Пересчёт ответственного для существующих записей охватывает и контрагентов 1С без портального аккаунта (role=unregistered).
- (assumption) Действие «Установить скидку N %» ставит discount_percent; связь с флагом is_sale не задана источником.
