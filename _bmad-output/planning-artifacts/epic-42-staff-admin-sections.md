# FREESPORT — Эпик 42: Разделы админки для менеджеров, маркетинга и руководителя

## Overview

Документ раскладывает спецификацию `_bmad-output/specs/spec-staff-admin-sections/` на реализуемые стори. Требования выведены **не из PRD**, а из спецификации, согласованной с Alex 08.10.2026: в PRD и Architecture нет положений о ролях сотрудников. PRD и Architecture служат только источником ограничений реализации.

Состав каждого раздела (колонки, фильтры, поля для правки, поля только для чтения, скрытые поля, действия) задан в `section-contents.md`. Стори ссылаются на него и не дублируют таблицы.

## Requirements Inventory

### Functional Requirements

**Группа A — роли сотрудников и закрытие доступа**

FR-42-01: В каждой среде есть группы «Менеджеры», «Маркетинг» и «Руководители» с закреплённым набором прав. Они создаются миграцией, а не вручную.
FR-42-02: Основная `/admin/` доступна только суперпользователю. Сотрудник любой из трёх ролей получает отказ.
FR-42-03: Ни одна форма, доступная сотрудникам, не позволяет установить `is_superuser`, `is_staff`, группу или право вне трёх ролей.
FR-42-04: Сотрудникам трёх ролей недоступны:
- обмен с 1С (`Is1CExchangeUser`);
- страница запуска импорта;
- API метрик синхронизации;
- `include_inactive` каталога.

Доступ к ним остаётся у суперпользователя и у обладателя явного права. Для учётной записи обмена это `integrations.can_exchange_1c`.

**Группа B — регионы и ответственный менеджер**

FR-42-05: Правило региона (`ManagerRoutingRule`) ссылается на учётную запись менеджера. На один код региона или одну страну допускается одно активное правило. Резервное правило указывает на руководителя.
FR-42-06: Есть справочник названий регионов по кодам ИНН 01–99, включая 90–95 и 99. Коды без активного правила выводятся списком «Не распределены».
FR-42-07: У клиента есть поле «Ответственный менеджер» и признак «назначен вручную».
FR-42-08: Ответственного назначает правило региона:
- при регистрации;
- при верификации и привязке к 1С;
- при импорте контрагента из 1С;
- при смене ИНН или страны.

Назначение с признаком «вручную» эти события не перезаписывают.
FR-42-09: Есть разовый идемпотентный пересчёт ответственного для всех существующих клиентов, включая контрагентов 1С с ролью `unregistered`. Он выдаёт отчёт: сколько назначено, сколько ушло на резервное правило, сколько пропущено из-за ручного назначения.
FR-42-10: Письмо о регистрации B2B-клиента уходит менеджеру, определённому по той же таблице правил.
FR-42-11: При смене менеджера в правиле региона клиенты этого региона без ручного назначения переходят к новому менеджеру.

**Группа C — раздел менеджера**

FR-42-12: Список клиентов показывает только тех, у кого ответственный — этот менеджер. Сотрудников в нём нет. Колонки, фильтры и поиск — по `section-contents.md`. Контрагенты 1С без портального аккаунта по умолчанию скрыты.
FR-42-13: В карточке клиента правятся контакты, B2B-данные, реквизиты компании, адреса и флаг «активен». Роль, вид цен, связь с 1С и ответственный менеджер — только для чтения. Поля из блока «Не показывать» в форме отсутствуют.
FR-42-14: Для своих клиентов доступны:
- страница подтверждения B2B — единственное место назначения роли;
- верификация и отказ;
- блокировка и **разблокировка** (новое действие);
- сброс пароля;
- привязка к контрагенту 1С.
FR-42-15: Заказы видны только по своим клиентам, в списке — мастер-заказы. Правятся трек-номер, дата доставки и комментарий. Статус и остальные поля — только чтение. Экспорт CSV выгружает только свои заказы.
FR-42-16: На главной раздела есть счётчики «Заявки на верификацию: N, старейшая — X дней» и «Новые заказы: N» со ссылками на отфильтрованные списки.
FR-42-17: Фильтр по ответственному действует везде:
- список и поиск;
- карточка по прямому URL;
- массовые действия и экспорт;
- страницы подтверждения B2B и смены пароля.

На чужого клиента и чужой заказ система отвечает 404.

**Группа D — раздел маркетинга**

FR-42-18: Баннеры, новости и блог доступны маркетингу полностью.
FR-42-19: Рубриками новостей и блога (`common.Category`) можно управлять из раздела маркетинга.
FR-42-20: Маркетинговый вид товаров — по `section-contents.md`. Метки правятся в списке и в карточке. Название, бренд, категория и `discount_percent` только для чтения. Остальные поля, включая описание, скрыты. Назначать скидку маркетинг не может (решение Alex 08.10.2026).
FR-42-21: Массовые действия над товарами — только поставить или снять каждую метку. Действий со скидкой нет.
FR-42-22: Бренды: флаг «показывать на главной», логотип, описание. Категории на главной: картинка, порядок, активность.
FR-42-23: На главной раздела маркетинга показаны число активных подписчиков и прирост за 30 дней. Списка и экспорта подписчиков нет.

**Группа E — раздел руководителя**

FR-42-24: Руководитель видит разделы менеджера и маркетинга целиком, без фильтра по ответственному. Ему же видны заказы без клиента (`Order.user` пусто — наследие `order_export`).
FR-42-25: Руководитель управляет сотрудниками:
- создаёт учётную запись;
- блокирует и разблокирует её;
- сбрасывает пароль;
- назначает одну из трёх групп.

Создать суперпользователя и редактировать других руководителей он не может.
FR-42-26: Руководитель ведёт таблицу правил регионов: «код региона или страна → менеджер», с названиями субъектов и блоком «Не распределены».
FR-42-27: Руководитель переназначает клиентов: вручную одному клиенту (ставится признак «вручную») и массово от менеджера A менеджеру B.
FR-42-28: Сводка руководителя:
- заявки на верификацию в ожидании по менеджерам, со сроком ожидания;
- заказы и выручка за период по менеджерам и регионам;
- новые регистрации за период;
- верифицированные клиенты без заказов.
FR-42-29: Руководителю доступны получатели уведомлений (`NotificationRecipient`) и настройки бонусной программы (`BonusProgramSettings`). Операции бонусов (`BonusTransaction`) — только просмотр.

**Группа F — журнал действий сотрудников**

FR-42-30: Каждое действие из перечня в `section-contents.md` пишет запись `AuditLog` с автором, объектом и временем. Действия, которые уже пишут запись, не дублируются.
FR-42-31: Руководитель видит ленту журнала с формулировками вида «кто — что сделал — с кем» и фильтрами по сотруднику и периоду. IP-адреса, User-Agent и сырого JSON в ленте нет.

### NonFunctional Requirements

NFR-42-01: Изменения покрыты тестами по стандарту проекта (`backend/docs/testing-standards.md`): общее покрытие ≥ 75% в CI, проверки доступа — критический модуль, ≥ 90%.
NFR-42-02: У каждой проверки доступа есть негативный тест. Для каждой роли и каждого раздела, включая прямые URL карточек и служебных страниц, проверяется отказ. Позитивных тестов недостаточно.
NFR-42-03: Интерфейс, комментарии и docstrings — на русском.
NFR-42-04: Число SQL-запросов на странице списка (клиенты, заказы, товары, журнал) не зависит от числа строк. Проверяется тестом с `django_assert_max_num_queries` или аналогом.
NFR-42-05: Обмен с 1С на проде продолжает работать после смены проверок `is_staff`. Импорт, выгрузка заказов и статусов проходят без ошибок доступа.
NFR-42-06: Если затронуты DRF-эндпоинты (метрики синхронизации), обновлён `docs/api/openapi.yaml` и проходит `check_openapi_sync`.

- **Описание товара перезаписывает импорт 1С** (`variant_import.py:1178`), поэтому маркетингу оно не даётся.
- **Назначение скидки исключено из эпика** (решение Alex 08.10.2026). `discount_percent` — только подпись на бейдже (`products/models.py:374`), цену не меняет. В разделе маркетинга поле только для чтения.
- **Гостевого оформления заказа нет:** `OrderViewSet.get_permissions` требует `IsAuthenticated` (`orders/views.py:37`).

### Story 42.8: Сводка руководителя

As a руководитель,
I want видеть на одной странице очередь заявок, заказы и выручку по менеджерам и регионам,
So that я вижу загрузку отдела и задержки без выгрузок и ручного подсчёта.

**Закрывает:** FR-42-28.

**Контекст:** `CustomerSyncMonitor.get_business_metrics` (`common/services/customer_sync_monitor.py:154`) считает метрики синхронизации, а не продаж: для сводки он годится только как образец кэширования. Выручка считается по мастер-заказам, чтобы не задваивать суммы субзаказов.

**Given** заявки на верификацию в ожидании у разных менеджеров
**When** руководитель открывает сводку

**And** заявки клиентов без ответственного выделены отдельной строкой

**Given** заказы за выбранный период
**When** руководитель меняет период
**Then** число заказов и выручка пересчитываются по менеджерам и по регионам
**And** выручка считается по мастер-заказам, сумма субзаказов не добавляется второй раз

**Given** период
**When** сводка отрисована
**Then** видно число новых регистраций за период и число верифицированных клиентов без единого заказа, со ссылкой на их список

**Given** менеджер или маркетолог
**When** он открывает URL сводки
**Then** получает отказ

**Given** 30 менеджеров и 10 000 заказов
**When** открывается сводка
**Then** число SQL-запросов не зависит от числа менеджеров и заказов (агрегация в БД)
