## Intent

**Problem:** На странице «Каталог» подборки «Акция», «Новинка» и «Лидеры продаж» открываются только по ссылке с главной: в блоке «Фильтры» выбрать их нельзя.

**Approach:** Добавить в блок «Фильтры» под ценой и над «Торговой маркой» три чекбокса, как «В наличии». Одновременно выбран только один из них, по умолчанию все пустые, повторное нажатие снимает выбранный чекбокс и фильтр.

</frozen-after-approval>

## Implementation Notes

- Backend не меняется: `ProductFilter` уже принимает `is_promo`, `is_new`, `is_hit`, а `visible-categories` и `visible-brands` применяют те же фильтры.
- Соответствие подписей: «Акция» → `is_promo`, «Новинка» → `is_new`, «Лидеры продаж» → `is_hit` (как в `frontend/src/config/quickLinks.tsx`).
- Выбор хранится в состоянии и зеркалится в URL по схеме `inStock`. Значение, производное только от URL, давало бы лишний запрос со старым бейджем со второй страницы и задержку отметки чекбокса.
- Переход с главной по `?is_promo=true` показывает соответствующий чекбокс отмеченным.
- Несколько флагов в адресе (`?is_new=true&is_hit=true`): остаётся первый по порядку чекбоксов, остальные убирает канонизация, сервер разбирает так же. Иначе были бы отмечены два чекбокса.
- Кнопка «Сбросить» теперь снимает три чекбокса: прежняя причина оставлять бейджи («в сайдбаре как фильтр не показаны») для них больше не действует. `is_sale` чекбокса не имеет и по-прежнему переживает сброс.
- Выбор чекбокса снимает `is_sale`, иначе выдачу сужал бы невидимый фильтр. `is_sale` тоже держится в состоянии: значение только из URL давало лишний запрос с пересечением подборок до commit адреса (находка ревью).
- `/electric/catalog` — отдельная страница, в объём не входит.
- Проверено в браузере на локальном стенде: выбор, переключение, снятие, «назад», два флага в адресе, «Сбросить». Выдача: Акция 2, Новинка 5, Лидеры продаж 7 из 1134.
- Изменены `CatalogPageClient.tsx`, `catalogQuery.ts` и их тесты в `frontend/src/app/(blue)/catalog/`.
