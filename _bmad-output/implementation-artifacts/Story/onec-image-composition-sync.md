## Story

As a **владелец каталога**,
I want **чтобы состав и порядок фотографий товара на сайте повторяли то, что заведено в 1С, а уже перенесённые картинки не считались потерянными**,
so that **обновлённое в 1С фото становилось главным на карточке, снятое — исчезало, а счётчик ошибок импорта означал реальные потери файлов**.

## Acceptance Criteria

1. **AC1 — уже перенесённая копия не считается потерей.** При отсутствии исходного файла `_save_image_if_not_exists` проверяет целевой путь в хранилище: если копия есть — возвращает её путь и учитывает как `images_skipped`. `images_errors` растёт только когда нет ни исходника, ни копии.
2. **AC2 — `Product.base_images` зеркалит `goods.xml`.** При импорте из XML состав и порядок берутся из выгрузки: картинки, которой в выгрузке нет, в списке не остаётся; порядок списка совпадает с порядком тегов `<Картинка>`; первой в списке становится первая картинка 1С.
3. **AC3 — нулевое разрешение состав не меняет.** Если при зеркалировании не разрешилась **ни одна** картинка выгрузки (нет ни исходников, ни копий, либо все отсеяны порогом), `base_images` и состав варианта остаются прежними. Отдельный тест обязателен — это единственная защита от потери каталога при сбое обмена.
4. **AC4 — отсутствие тега `<Картинка>` состав не меняет.** Товар, у которого в `goods_data` нет ключа `images`, проходит импорт с нетронутым `base_images`. Поведение уже обеспечено guard'ом `"images" in goods_data` (`:556`, `:614`) — тест его фиксирует, чтобы правка не сняла.
5. **AC5 — `ProductVariant.main_image` переназначается по `offers.xml`.** При импорте из XML первая картинка выгрузки становится `main_image`, остальные — `gallery_images` в порядке 1С; уже заполненное `main_image` заменяется. Защиты AC3 и AC4 действуют так же.
6. **AC6 — порог размера считается и по копиям в `media`.** `_get_effective_min_size` определяет эффективный порог по фактически доступному файлу: исходнику либо перенесённой копии. Мелкое превью, ранее отсеянное основным порогом 100 КБ, не возвращается в состав после того, как исходники подчищены.
7. **AC7 — режим сканирования каталога остался аддитивным.** Вызовы из `integrations/tasks.py` и `import_images_from_1c` состав не режут и порядок не переставляют. Тест фиксирует: у товара с существующим `base_images` прогон сканирования только дописывает в хвост.
8. **AC8 — `import_images_from_1c` не падает на заполненном `main_image`.** Ветка дедупликации галереи режет путь по `.name`; `TypeError: argument should be a str or an os.PathLike object` не возникает.
9. **AC9 — каждый новый тест падает до правки.** Прогнать и показать RED в Debug Log, иначе тест ничего не ловит.
10. **AC10 — проверено на проде после выката.** ✅ Закрыт 2026-08-28 прод-замером после ручного деплоя и полной выгрузки 1С (замеры — в `verification.md`). Исходная формулировка: закрывается **после** деплоя и следующей выгрузки 1С, не мержем: статус `done` ставится по прод-замеру, а не по зелёным тестам. `images_errors` в goods-сессии падает с 253 до величины, объяснимой реально отсутствующими файлами; товар 9194 отдаёт `main_image` = `…_fb2f7292-….jpg` (розовая гантель 1,0 кг). Запросы — в `verification.md`.

## Dev Notes

### Как работает сейчас (проверено чтением на `1c0fac85`)

`_save_image_if_not_exists` (`:380`) — порядок операций: `source_path.exists()` (`:403`) → размер против `effective_min` (`:409-414`) → сборка `destination_path` (`:416-422`) → `default_storage.exists(destination_path)` (`:425-427`, `images_skipped`, возврат пути) → копирование (`:435-441`, `images_copied`). Именно на первой проверке всё и ломается: 1С подчищает `import_files` после импорта (`import_products_from_1c.py:878-904`), а `goods.xml` с теми же товарами приходит снова — и каждая уже перенесённая картинка засчитывается ошибкой.

`_import_base_images` (`:647`) аддитивен: существующий список предзагружается в `base_images`/`seen_filenames` (`:665-675`), новые пути дописываются в хвост (`:694`). `_import_variant_images` (`:934`) аддитивен и не переназначает главное: `main_image_set = bool(variant.main_image)` (`:949`), далее `if not main_image_set` (`:987`).

`_get_effective_min_size` (`:362`) — приватный метод, вызывается только из `:677` и `:970`, внешних вызывающих нет (проверено grep по `backend/`), поэтому смена сигнатуры безопасна. Смотрит только на исходники. После T1 исходников на проде обычно нет — без T4 порог упадёт до резервных 8 КБ и мелкие превью вернутся в состав. **T4 нельзя откладывать: он не улучшение, а компенсация побочного эффекта T1.**

Полная карта кода — в `_bmad-output/specs/spec-image-sync-from-1c/current-behavior.md`.

### Разделение режимов — критично

Оба метода состава вызываются из четырёх мест:

| Вызов | Источник состава | Режим |
|---|---|---|
| `variant_import.py:557`, `:615` | `goods.xml` | **зеркало** |
| `variant_import.py:830`, `:917` | `offers.xml` | **зеркало** |
| `integrations/tasks.py:301`, `:311` | glob по каталогу | аддитивный |
| `import_images_from_1c.py:199`, `:208` | glob по каталогу | аддитивный |

Сканирование каталога источником истины не является — там список собран по остаткам на диске, зеркалирование по нему обрежет всё, чего на диске уже нет. Механизм: keyword-only `mirror_composition: bool = False`. Оба сканирующих вызова передают аргументы по ключевым словам и default подхватят автоматически — их править не нужно.

### Гарантии, которые нельзя потерять

- **Нулевое разрешение ≠ «фото удалили»** (AC3). Сбой обмена, подчищенный каталог, отсеявший всё порог — любой из этих случаев даёт пустой `resolved`, и состав обязан остаться прежним.
- **Нет тега `<Картинка>` ≠ «фото удалили»** (AC4). Guard `"images" in goods_data` уже стоит на `:556` и `:614` — не снимать. Удаление всех фото товара через обмен не поддерживается осознанно: отличить «в 1С сняли всё» от «выгрузка сломалась» нечем.
- **Инкрементальный режим сам защищает остальное:** товара нет в файле — состав не трогается.
- **Ожидаемый побочный эффект, не дефект:** картинка, попавшая в состав только сканированием каталога и отсутствующая в `goods.xml`, после зеркалирующего прогона из списка уйдёт. XML — источник истины, так и задумано.
- **В аддитивном режиме сохранение остаётся безусловным.** `_import_variant_images` сегодня всегда доходит до `variant.save(update_fields=[...])` (`:1000-1001`). Ранний выход добавляется **только** для режима зеркала при пустом `resolved` — не распространяй его на аддитивный путь.

Вынесено осознанно, каждый пункт — отдельная работа:
