## Критерии приёмки

Сохранены четыре AC эпика. Ни один AC этой истории пока не принят.

### AC1. Индивидуальные решения и полнота реестра

**Дано:** редакторские таблицы отчёта от 10.09.2026, страницы 11–12, и восстановленный контекст.

**Когда:** владелец рассматривает каждый элемент и его вхождения.

**Тогда:** все 19 элементов имеют одно из окончательных решений «заменить», «оставить», «не относится к публичному интерфейсу», индивидуальное основание, исполнителя, согласующего, дату, статус и способ проверки. Для замены записаны точные «было → стало» и место изменения. Передача владельцу CMS является назначением работы, а не четвёртым окончательным решением.

В PDF указаны **68 срабатываний по 19 словам и фрагментам**, а не 19 отдельных мест. Если одно слово встречается в разных смысловых контекстах, у основной записи создаются подзаписи по URL/фрагменту с собственными решениями; нельзя распространять решение для модели товара на одноимённую подпись интерфейса. Для «блог» и «фитнес» PDF показывает 10 URL и «ещё 10 стр.». Получить полную выгрузку/HTML исходного отчёта у владельца либо зафиксировать ограничение и отдельно согласованный способ восстановления покрытия. Текущий обход сайта не выдавать за полный исторический список 68 срабатываний.

### AC2. Проверяемые изменения и исторические доказательства

**Дано:** согласованные решения «заменить» и две ранее выполненные правки.

**Когда:** исполнитель применяет только утверждённые изменения и проверяет публикацию.

**Тогда:** для CMS сохранены ответ API и опубликованная страница после фактической ревалидации/обновления ISR; для исходников — итог релевантных тестов/сборки и браузерная проверка. Доказательства содержат дату, URL, окружение, точный фрагмент, а для кода — commit и итоговый exit code проверок. Обновление API без обновления страницы не закрывает строку.

`Breadcrumb` и `CRM-системе` включены как исторически выполненные изменения со ссылкой на проверку 13.09.2026, без повторной замены. При свежей проверке регрессия оформляется отдельно; исторический успех не объявляется текущей приёмкой. Для затронутого видимого интерфейса соблюдён NFR-41-08: аноним, пустая корзина, без cookie, браузер и серверный HTML; отдельно проверяются доступные имена, если они изменялись.

### AC3. Сохранность наименований и технических контрактов

**Дано:** латинское слово, возможный бренд/модель, email-адрес, URL или технический идентификатор.

**Когда:** определяется источник и готовится решение.

**Тогда:** нет автоматического перевода или массовой замены. Сохраняются адрес доставки почты, ссылки, slug/query-параметры, поля API, SKU/идентификаторы 1С и официальное написание подтверждённых наименований. Видимая подпись `email` или `brand` проверяется отдельно от технического поля. Классификация «бренд», «модель», «закреплённый термин» подкрепляется источником, а не выводится из регистра букв или начальной группы эпика.

### AC4. Корректная интерпретация результата

**Дано:** заполненный реестр с согласованными решениями и доказательствами.

**Когда:** подготавливается итог истории.

**Тогда:** раздельно перечислены выполненные замены, обоснованные сохранения/исключения и незавершённые внешние действия. Нет юридического заключения, утверждения об установленном нарушении по одному словарному срабатыванию или гарантии исчезновения всех строк сканера. Отсутствие решения/доказательства означает открытую строку и препятствует `done`. Повторный запуск исходного сканера фиксируется отдельно, только если действительно выполнен.
