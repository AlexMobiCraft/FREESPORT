## Постановка

**Цель.** Поисковик получает различимые метаданные и canonical для каждой публичной категории; служебные фильтры не становятся отдельными посадочными страницами.

**Текущая реализация.** `frontend/src/app/(blue)/catalog/layout.tsx` статически вызывает `buildMetadata` для `/catalog`, а сама страница каталога является Client Component. Сервис категорий уже получает данные из `/api/v1/categories/`; в контракте есть также `/categories/{slug}/`.

**Обязательные решения до реализации.**

1. Подтвердить, что все публичные `?category=<slug>` — индексируемые посадочные страницы. Не включать в работу неизвестные/устаревшие slug без ответа API.
2. Утвердить шаблон title и description. Рекомендуемая форма: «<Название категории> — спортивные товары | OPTISPORT» и описание, которое содержит название категории, но не обещает наличие товара.
3. Согласовать обработку нескольких категорий и `category` вместе с прочими фильтрами. Рекомендуемое правило: собственные метаданные только для ровно одной валидной категории; при нескольких категориях или неизвестном slug canonical `/catalog`.

**Критерии приёмки.**

**Given** согласованный сценарий Story 41.13
**When** выполняется проверка AC1
**Then** `?category=<валидный slug>` отдаёт title, description и canonical с этим же единственным параметром category.

**Given** согласованный сценарий Story 41.13
**When** выполняется проверка AC2
**Then** Основной `/catalog` сохраняет существующие метаданные и canonical.

**Given** согласованный сценарий Story 41.13
**When** выполняется проверка AC3
**Then** `focusSearch`, page, сортировка, цены, наличие и бренд не создают самостоятельного canonical; они сохраняют canonical выбранной единственной категории или `/catalog`.

**Given** согласованный сценарий Story 41.13
**When** выполняется проверка AC4
**Then** Невалидная категория не получает вымышленного имени и не бросает 500.

**Given** согласованный сценарий Story 41.13
**When** выполняется проверка AC5
**Then** Метаданные доступны в серверном HTML, а не появляются только после гидратации.

**Given** согласованный сценарий Story 41.13

**Then** Существующее отображение и URL-синхронизация фильтров каталога не меняются.

**Given** согласованный сценарий Story 41.13
**When** выполняется проверка AC7
**Then** В sitemap добавляются только действительно индексируемые адреса категорий либо фиксируется тестом, почему sitemap их не перечисляет.

**Технические ограничения.**

- Не менять сигнатуру `buildMetadata`: по прежнему анализу у неё широкий blast radius.
- Нужна server wrapper для каталога или иной серверный слой, которому доступны `searchParams`; переносить интерактивную фильтрацию из текущего Client Component не требуется.
- Перед изменением символов выполнить GitNexus impact. Сейчас индекс GitNexus устарел относительно `c7785074`, поэтому сначала требуется его обновление пользователем по принятому в проекте правилу.

**Проверки.** Unit-тесты метаданных для базового каталога, валидной одной категории, неизвестной категории, нескольких категорий и category с прочими фильтрами; server-HTML проверка; `npm test`, `npm run lint`, `npx tsc --noEmit`, `npm run format:check`.
