# Исследование: вид цены в строках заказа сайта для 1С

Дата: 2026-11-12. Источники: код `develop` (`13d82ff`), исходники УТ 11.5.22.134 и БУС 8.1.0.40
(`C:\Users\1\DEV\1C-PROJECT`), данные `test_base` через COM (заказы до апреля 2026), таблица
`price_types` и заказы прода (только чтение). Прод-1С (БУС 8.1.0.45) не смотрели: она недоступна.

## 1. Что сайт отдаёт сейчас

`OrderExportService._create_products_element` (`backend/apps/orders/services/order_export.py:325`)
пишет в каждую строку `<ВидЦены><Ид/><Наименование/></ВидЦены>`. Вид цены **один на весь заказ**
и считается по `user.role` через `ONEC_EXCHANGE.PRICE_TYPE_BY_ROLE` (`settings/base.py:446`).
С ценой строки он расходится:

| Как считается цена строки (`get_price_for_user`) | Что уходит в `<ВидЦены>` |
|---|---|
| Акционная цена ниже цены роли | вид цен роли, а не акции |
| Поле роли пустое, откат на `retail_price` (≈52–54 % вариантов у Опт 1–3) | «Опт N» |
| `special_price` пуст, откат на `opt1_price` | «РРЦ» (роли нет в карте) |
| Роли `vip`, `special_price` | «РРЦ» (ролей нет в карте) |
| Неверифицированный B2B (платит розницу) | «Опт N» |
| `federation_rep` | «Партнер» без GUID; на проде нет `PriceType` для `federation_price` |

На проде 7 мастер-заказов: 5 у `special_price`, 1 у `vip`, 1 у `wholesale_level1`. То есть для 6 из 7
сайт уже сейчас пишет в XML неверное «РРЦ».

Цена фиксируется в момент добавления в корзину (`CartItem.price_snapshot`, `cart/models.py:152`,
`cart/views.py:157`, слияние гостевой корзины в `cart/signals.py:85`). При оформлении она переносится
в `OrderItem.unit_price` (`order_create.py:138`) без пересчёта. Из какого поля взята цена, нигде
не сохраняется.

На проде в `price_types` 11 строк: Опт 1–4, РРЦ, МРЦ, Тренерская, VIP цены, СПЕЦЦЕНА, акции
«АКЦИЯ ОКТЯБРЬ-26» (неактивна) и «АКЦИЯ НОЯБРЬ-26» (`e07feed3-d75a-11f1-9765-e734d5c16693`, активна).
Строки для `federation_price` нет.

## 2. Что делает БУС при загрузке заказа

- `БУС_ЗагрузкаСервер.ОбработатьИнформациюОТовареДокументаXDTO` (стр. 506–560) **тег `<ВидЦены>`
  строки не читает**. Из строки берутся Ид, Наименование, Количество, Коэффициент, ЦенаЗаЕдиницу,
  Сумма, Налоги и **`ЗначенияРеквизитов` строки целиком** (таблица Наименование/Значение).
- Реквизиты строки табличной части заполняются по таблице
  `СохраненныеНастройки.НастройкиОбменаЗаказов.СоответствияРеквизитов.ВсеСоответствияТабличныхЧастейДокументов`
  (стр. 1367–1393), строки обрабатываются по порядку. Затем вызывается `ПересчитатьСтрокуДокумента`
  (НДС, суммы, скидки). Вид цены там не заполняется.
- Режимы заполнения (`ПолучитьЗначениеРеквизитаДокументаПоСоответствию`, стр. 1624–2431):
  - «Сопоставление по свойству документа» читает **`ЗначенияРеквизитов` шапки** даже для строки.
    Разные виды цен в разных строках так не передать.
  - `<Свой алгоритм>` выполняется через `ОбщегоНазначения.ВыполнитьВБезопасномРежиме` с параметрами
    `[Документ]`, `[НоваяСтрока]`, `[ДокументXML]`, `[СтруктураНастроек]`, `[Результат]`.
    **Дефект БУС:** плейсхолдер `[СтрокаXML]` заменяется на `Параметры.СтрокаXML`, но этот ключ в
    структуру `Параметры` не добавляется (стр. 2405–2427). Обращение к `[СтрокаXML]` упадёт.
    Обходной путь — найти строку в `[ДокументXML].Товары` по `КодСтроки` нашей `[НоваяСтрока]`.
  - Безопасный режим запрещает `Выполнить`/`Вычислить`, `ПараметрыСеанса`,
    `ПользователиИнформационнойБазы` и модуль `ДлительныеОперации`. Чтение справочников,
    `ПолучитьСсылку` и `ОбщегоНазначения.СсылкаСуществует` разрешены.
- Расширенный режим формы «Настройка заполнения реквизитов загружаемых документов» позволяет выбрать
  для строки ТЧ режим `<Свой алгоритм>` (`ПолучитьМассивИсточникДанных`). В руководстве 8.1.0.45
  режим описан одной строкой, плейсхолдеры не документированы.

### Настройки узла «Выгрузка на сайт» (test_base)

- Шапка: `Соглашение` — **«Фиксированное значение» = «Стандартное»**
  (`2c0a6c2f-bd0d-11ea-81c4-00155d3cae02`). Тег `<Соглашение>` и реквизит «Соглашение» из XML сайта
  БУС не читает, так что смена соглашения на сайте ничего не даст.
- Строки `Товары`: строка соответствия **`ВидЦены` уже заведена** — «Фиксированное значение», пусто.
  `КодСтроки` (предопределённый алгоритм) стоит в таблице раньше `ВидЦены`.
- Для 8.1.0.45 на проде нужно сверить у администратора 1С и поведение модуля (исходник в репозитории
  только бинарный `.cfe`), и состав таблицы соответствий.

## 3. Что значит «правильный вид цены» в практике менеджеров (test_base)

Ручные заказы (с 01.10.2025) почти все оформлены на соглашениях «Акция <МЕСЯЦ>». Такое соглашение
типовое, без сегмента, вид цен в шапке «Опт 1», вариант «Вид цен в шапке и виды цен по номенклатуре»,
в ТЧ «Товары» 300–1150 позиций с видом цен «Акция <МЕСЯЦ>» (цена в ТЧ не задана).

Строки ручных заказов на соглашении «Акция МАРТ»:

| Позиция есть в ТЧ соглашения | Вид цены строки | Строк |
|---|---|---|
| да | Акция МАРТ | 6121 |
| да | СПЕЦЦЕНА / РРЦ / Опт 1 / VIP / пусто | 205 |
| нет | Опт 1 | 10233 |
| нет | VIP цены | 1278 |
| нет | СПЕЦЦЕНА, Дилерская, SS26-1, Опт 2/3/4, Партнер, Тренерская, РРЦ | ~1300 |

Итого: **акционная позиция получает вид цен акции, остальные — вид цен клиента**. Один документ
содержит несколько видов цен.

Заказы с сайта в test_base: 94 строки в 71 документе. Соглашения «для проведения», «Стандартное»
или пустое, **`ВидЦены` пуст во всех строках**.

Виды цен акций в test_base называются «Акция МАРТ» (`a151b0b5-…`), на проде — «АКЦИЯ НОЯБРЬ-26».
Есть закрытое «распродажа» и действующее «РАСПРОДАЖА». Поиск по наименованию регистр не различает,
поэтому сопоставление по имени здесь опасно.

## 4. Влияние `ЗаказКлиента.Товары.ВидЦены` в УТ

- При проведении на цену и согласование не влияет: проверок «цена не ниже минимальной» или
  «отклонение от вида цен» в модуле объекта нет. Поле уходит в запрос данных для движений
  (`ManagerModule`, стр. 2492) и показывается в форме.
- Заполняет его только `ЗаполнитьУсловияПродажПоСоглашению` или интерактивный пересчёт. БУС создаёт
  документ без `Заполнить` и этого не вызывает. Поэтому соглашение «Акция …» в шапке **само по себе
  вид цены в строках не заполнит**.
- Если менеджер позже нажмёт «Заполнить цены по соглашению», УТ пересчитает строки по соглашению
  (на «Акция …» — «Опт 1» вне ТЧ акции) и затрёт цены сайта.

## 5. Варианты решения

**A. Настройка БУС `<Свой алгоритм>` для `Товары.ВидЦены` (рекомендуется).** Сайт кладёт GUID вида
цены в `ЗначенияРеквизитов` строки, БУС в строке `ВидЦены` выполняет алгоритм ниже. Расширение не
меняется. Перед продом нужна проверка на test_base и сверка с 8.1.0.45.

```bsl
[Результат] = Справочники.ВидыЦен.ПустаяСсылка();
Попытка
	Для Каждого СтрXML Из [ДокументXML].Товары Цикл
		Если СтрXML.КодСтроки <> [НоваяСтрока].КодСтроки Тогда Продолжить; КонецЕсли;
		Если СтрXML.ЗначенияРеквизитов <> Неопределено Тогда
			Найд = СтрXML.ЗначенияРеквизитов.Найти("ВидЦеныИд", "Наименование");
			Если Найд <> Неопределено И ЗначениеЗаполнено(Найд.Значение) Тогда
				Ссылка = Справочники.ВидыЦен.ПолучитьСсылку(Новый УникальныйИдентификатор(Найд.Значение));
				Если ОбщегоНазначения.СсылкаСуществует(Ссылка) И НЕ Ссылка.ПометкаУдаления Тогда
					[Результат] = Ссылка;
				КонецЕсли;
			КонецЕсли;
		КонецЕсли;
		Прервать;
	КонецЦикла;
Исключение
	[Результат] = Справочники.ВидыЦен.ПустаяСсылка();
КонецПопытки;
```

**B. Патч расширения БУС.** Читать `<ВидЦены><Ид>` в `ОбработатьИнформациюОТовареДокументаXDTO`
и добавить предопределённый алгоритм. Надёжнее A, но патч приходится повторять при каждом обновлении
БУС. Прецедент — патч контрагентов в `docs/integrations/1c/bus-extension-patch/`.

**C. Только смена соглашения на «Акция …».** Вид цены в строках не заполнит (п. 4). Соглашение
задано фиксированным значением, и для его передачи с сайта нужен режим сопоставления по
наименованию с риском коллизий (п. 3). Каждый месяц появляется новое соглашение. Шапка «Опт 1»
неверна для клиентов других уровней. Годится только как дополнение к A или B — если соглашение
нужно отчётам или менеджерам.

### Соглашение акции в шапке (решение владельца 12.11.2026)

- Реквизиты, которые БУС берёт из соглашения, у «Стандартное» и у «Акция МАРТ/НОЯБРЬ»
  одинаковые: операция «Реализация», цена с НДС, рубли, график и форма оплаты пусты. «Операция» на узле
  задана фиксированно, а «Менеджер» по регламенту `order-manager-author-department-setup.md` от
  соглашения не зависит. Смена соглашения побочных изменений не даёт.
- Строка «Соглашение» (позиция 65) выполняется раньше «Партнер» и строк товаров. Значение ей нужно
  передать в шапке XML.
- Среди непомеченных соглашений без учёта регистра дублируются «РАСПРОДАЖА» (2), «Соглашение
  реализации» (261), «Комиссионное Детский мир» и «Выкуп РВБ ООО». Искать только среди
  `Статус = Действует` и принимать ровно одно.
- Вид цен и соглашение акции в test_base называются одинаково («Акция МАРТ»). На проде вид цен —
  «АКЦИЯ НОЯБРЬ-26»; имя соглашения нужно сверить с администратором.

```bsl
// GUID «Стандартного» — из текущей настройки узла на проде (в test_base 2c0a6c2f-…)
[Результат] = Справочники.СоглашенияСКлиентами.ПолучитьСсылку(Новый УникальныйИдентификатор("2c0a6c2f-bd0d-11ea-81c4-00155d3cae02"));
Попытка
	Реквизиты = [ДокументXML].ЗначенияРеквизитов;
	Найд = ?(Реквизиты = Неопределено, Неопределено, Реквизиты.Найти("Соглашение", "Наименование"));
	Если Найд <> Неопределено И ЗначениеЗаполнено(Найд.Значение) Тогда
		Запрос = Новый Запрос("ВЫБРАТЬ ПЕРВЫЕ 2 С.Ссылка КАК Ссылка ИЗ Справочник.СоглашенияСКлиентами КАК С
		|ГДЕ С.Наименование = &Имя И НЕ С.ПометкаУдаления
		|	И С.Статус = ЗНАЧЕНИЕ(Перечисление.СтатусыСоглашенийСКлиентами.Действует)
		|	И (С.ДатаНачалаДействия = ДАТАВРЕМЯ(1, 1, 1) ИЛИ С.ДатаНачалаДействия <= &Дата)
		|	И (С.ДатаОкончанияДействия = ДАТАВРЕМЯ(1, 1, 1) ИЛИ С.ДатаОкончанияДействия >= &Дата)");
		Запрос.УстановитьПараметр("Имя", Найд.Значение);
		Запрос.УстановитьПараметр("Дата", НачалоДня(ТекущаяДатаСеанса()));
		Выборка = Запрос.Выполнить().Выбрать();
		Если Выборка.Количество() = 1 И Выборка.Следующий() Тогда [Результат] = Выборка.Ссылка; КонецЕсли;
	КонецЕсли;
Исключение
КонецПопытки;
```

Перечисление `СтатусыСоглашенийСКлиентами.Действует` есть в конфигурации. `Запрос.Выполнить()`
проверка БСП пропускает: она вырезает из текста `ВЫПОЛНИТЬ()` без аргументов. Сам алгоритм ещё нужно
прогнать на test_base.

## 6. Что нужно на стороне сайта при любом из вариантов A/B

Вид цены строки — это вид цен **того поля, из которого взята цена**, а не роль клиента. Зафиксировать
его надо в тот же момент, что и `price_snapshot`. Затем выгрузить его в строку: `<ВидЦены>`
(для B и совместимости) плюс `ЗначениеРеквизита` `ВидЦеныИд` (для A).
