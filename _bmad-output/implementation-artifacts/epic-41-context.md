# Epic 41 Context: Устранение недочётов аудита сайта optisport.ru

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Подготовить сайт к запуску: сбор ПДн и оплата соответствуют ФЗ-152, 38-ФЗ, ЗоЗПП и политике ПДн, заголовки безопасности приходят на всех ответах без дублей, в поиске сайт представлен корректно. Требования взяты из внешнего аудита, а не из PRD; цель — соответствие закону, а не зелёный отчёт. Эпик закрыт, когда критичные замечания по ПДн устранены по существу (кроме чекбокса на форме входа — для него есть обоснование), фантомных адресов в обходе нет, заголовки не дублируются. После повторного аудита открыт только `/checkout` — его закрывают 41.10–41.12.

- Story 41.0: Несуществующие адреса отдают настоящий 404

- Story 41.2: Фиксация согласия при привязке к записи 1С
- Story 41.3: Честный текст согласия в форме подписки
- Story 41.4: Торговая информация и ссылка на политику при оплате
- Story 41.5: Единый источник заголовков безопасности и их доставка во все локации
- Story 41.6: Уникальные метаданные, корректное соцпревью и JSON-LD
- Story 41.7: Номера в реестре операторов ПДн и обоснование по форме входа
- Story 41.8: Текстовый разделитель между бейджем, брендом и названием товара
- Story 41.9: Аудитируемость журнала согласий — версия текста и источник
- Story 41.10: Оформление заказа и корзина глазами анонима
- Story 41.11: Раздельные согласия в подписке и канал рассылки при регистрации
- Story 41.12: Полная формулировка номера реестра, подвалы, строка о политике при входе, русская подпись цепочки

## Requirements & Constraints

- **Приёмка UI** — глазами анонима с пустой корзиной без cookie: приватное окно плюс серверный HTML через `curl`. Проверка под авторизованным пользователем с товарами не засчитывается.
- **Раздельные согласия.** В подписке два неотмеченных обязательных чекбокса: обработка ПДн (со ссылкой на политику) и рассылки по электронной почте, тексты не пересекаются. При регистрации чекбокс рассылки необязателен и называет канал.
- **Журнал согласий.** У записи есть дата, источник (подписка, регистрация, привязка 1С) и версия показанного текста. Изменённая формулировка получает новую версию, прежние сохраняются.
- **Без чекбокса согласия** на входе и в оформлении заказа — только информирование. Ссылка на политику стоит рядом с полями заказа. Под кнопкой входа — строка без слова «соглашаетесь», вне журнала и реестра версий.
- **Checkout.** Поля формы видит только авторизованный с непустой корзиной, в серверном HTML их нет. Блок «условия возврата + поддержка» на корзине и оформлении виден всегда. Нулевой итог не показывается.
- **Условия возврата** — это `/partners#returns`, а не `/oferta` и не `/returns`.
- **Номер оператора 26-22-003980** пишется полной формулировкой «Регистрационный номер в реестре операторов, осуществляющих обработку персональных данных»: на `/requisites`, в трёх подвалах и в политике. Номер лицензиара 26-22-004188 — только на `/requisites`. Политика хранится в БД и правится в админке: это шаг выката, а не коммит.
- **Несуществующий адрес** отдаёт HTTP 404. Если backend недоступен, 404 вслепую не отдаётся.
- **Качество.** Покрытие ≥ 70% (≥ 90% для критичных модулей), порог по CI. Новые элементы доступны с клавиатуры, axe-core чист. Отказ от cookie не сложнее согласия. Если меняется контракт API — синхронизировать `openapi.yaml` и типы фронта.
- **Вне объёма:** ужесточение CSP, 2FA в админке, SEO категорий каталога.

## Technical Decisions

- **Заголовки ставит тот, кто отдаёт ответ.** nginx — статику, медиа, картинки товаров и `/health`, плюс HSTS везде (общий сниппет, потому что `add_header` в `location` замещает унаследованные). Next — HTML. Django — `/api/` и `/admin/`. Нельзя сломать оптимизацию изображений Next, 1С, YuKassa, виджеты CDEK и Boxberry.
- **CSP:** добавляется только `frame-ancestors`. HSTS с явным `max-age`, без `preload`.
- **404 отдаёт middleware** (работает до стриминга). Список CMS-слагов берётся из API и кэшируется с явным TTL.
- **`/subscribe/`:** флаги `pdp_consent` и `marketing_consent` (строго `true`), у каждого своя версия текста. Старый формат получает 400 `consent_text_outdated`. Образец — регистрация. Миграции не нужны.
- **Сессия восстановлена**, когда `isInitialized` в `AuthProvider`. Загрузку корзины отличать от пустой.
- **Редирект после входа.** `next`/`redirect` проверяются по origin после разбора URL; `//`, `/\` и `javascript:` отбрасываются.

## UX & Interaction Patterns

- UX-спецификации нет. Чекбоксы делаются по образцу `pdp_consent` в форме подписки (`useId`, `aria-describedby`), кнопки — `Button` из `@/components/ui`.
- Кнопка отказа от cookie визуально равна «Принять». Выбор можно изменить из подвала.
- Состояния `/checkout`: для анонима — приглашение войти; при пустой корзине — пустое состояние со ссылкой в каталог; при загрузке — индикатор, отличимый от пустой корзины; при ошибке — повтор.
- Цепочка: `aria-label="Навигационная цепочка"`. Разделитель бейдж/бренд/название не меняет внешний вид.

- Решение 41.3 «один чекбокс» отменено и заменено 41.11. Удаление формы с `coming-soon` в силе.

- Редакция 3 обоснования по форме входа (41.12) — только после мёрджа 41.10. `/login?next=%2Fcheckout` из 41.10 должен пережить исправление редиректа.
- 41.12 ломает тесты подвала из 41.4 и поиск цепочки по подписи — обновить их.
