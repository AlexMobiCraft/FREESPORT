## Проблема

Сканер читает HTML, который отдаёт сервер. На трёх типах страниц H1 в этом HTML нет или он пустой: заголовок появляется только после гидратации и клиентских запросов.

Замер по всем 30 адресам отчёта (число `<h1` и его текст в ответе сервера):

| Адрес | H1 в серверном HTML | Причина |
|---|---|---|
| `/home` | нет | `HeroSection` — клиентский компонент. До загрузки баннеров он рендерит заглушку `data-testid="hero-skeleton"` без заголовка (`components/home/HeroSection.tsx`, ветка `if (isLoading)`). H1 появляется только в ветках с баннером (`:158`, `:205`) |
| `/cart` | нет | `CartPage` до монтирования возвращает `CartSkeleton` (`components/cart/CartPage.tsx:43`). В заглушке вместо заголовка — `<Skeleton className="h-10 w-64 mb-8" />` (`components/cart/CartSkeleton.tsx`, «Title skeleton») |
| `/catalog`, 11 × `?category=…`, 3 подборки `?is_new/is_hit/is_sale=true` — 15 адресов в отчёте | `<h1>` есть, текста нет | В H1 стоит `<Skeleton>`, пока `isCategoriesLoading === true` (`app/(blue)/catalog/CatalogPageClient.tsx:1546-1554`). На сервере флаг всегда `true`: дерево категорий грузится в `useEffect` (`:630-650`) |

Остальные 13 адресов отдают H1 с текстом, их не трогать.

## Требуемое поведение

Каждая из перечисленных страниц отдаёт в серверном HTML ровно один `<h1>` с непустым текстом. После гидратации на странице по-прежнему ровно один H1. Внешний вид страниц не меняется.

Перед правкой любого символа выполни `npx gitnexus impact <символ> --direction upstream -r "C:\Users\1\DEV\FREESPORT"` и сообщи blast radius (AGENTS.md, раздел GitNexus). По grep ожидается узкий радиус: `HeroSection` используется только в `HomePage` (тема `/electric` использует свой `ElectricHeroSection`), `CartSkeleton` — только в `CartPage`, `CatalogPageClient` — только в `app/(blue)/catalog/page.tsx`.

### 1. `/home` — H1 страницы в `HomePage`

- В `components/home/HomePage.tsx` первым элементом контейнера добавить `<h1 className="sr-only">OPTISPORT — спортивные товары оптом</h1>`. `HomePage` помечен `'use client'`, но его статический JSX попадает в серверный HTML — этого достаточно.
- В `components/home/HeroSection.tsx` заголовки баннеров (`:158` — статический fallback, `:205` — баннер из API) перевести с `<h1>` на `<h2>`, классы оставить прежними. Иначе после загрузки баннеров на странице окажется два H1.

**Почему текст и `sr-only`.** Текст повторяет корневой заголовок сайта, принятый решением D7 (эпик 41): без слов «розница», превосходных степеней и латиницы. Видимый H1 изменил бы дизайн главной, а заголовок баннера меняется вместе с баннером и не описывает страницу. Визуально скрытый H1 — штатный приём доступности; класс `sr-only` в проекте уже используется.

### 2. `/cart` — заголовок в заглушке

- В `components/cart/CartSkeleton.tsx` заменить «Title skeleton» (`<Skeleton className="h-10 w-64 mb-8" />`) на `<h1 className="text-display-m font-bold text-text-primary mb-8">Ваша корзина</h1>` — тот же класс и текст, что в `CartPage.tsx:67`, `EmptyCart.tsx`, `CartError.tsx`. Тогда H1 будет во всех состояниях корзины, а при смене состояния не будет прыжка вёрстки.
- Заглушку хлебных крошек не трогать.

### 3. Каталог — начальный текст H1 с сервера

- В `app/(blue)/catalog/page.tsx` вычислить начальный текст заголовка и передать его в `CatalogPageClient` новым необязательным пропсом (например, `initialHeading?: string | null`):
  - нет параметра `category` (в том числе `/catalog` и подборки) → `'Каталог'`;
  - `category` есть и найден в дереве → `name` категории из `fetchCategories()` (та же функция, что в `generateMetadata`; запрос кешируется `next: { revalidate: 3600 }`, повторный вызов в рамках рендера бэкенд не нагружает);
  - `category` есть, но slug не найден → `'Каталог'` (так же поведёт себя клиент после загрузки дерева);
  - дерево не загрузилось, истёк таймаут или любая ошибка → `null`.
- Сверяй slug так же, как клиент: без `trim` (см. комментарий в `fetchInitialProducts`). Повторяющийся параметр — первое значение.
- Запрет из `fetchInitialProducts` (не ходить на бэкенд при клиентской навигации и при сохранённой сессии) на заголовок **не распространять**. Там он защищает некешируемый запрос выдачи, а дерево категорий берётся из кеша данных Next.
- В `CatalogPageClient.tsx` пробросить пропс через обёртку `CatalogPage` (`:1839`) в `CatalogContent` (`:371`). В H1 (`:1547`) при `isCategoriesLoading` показывать `initialHeading`, если он есть, и `Skeleton` только при `initialHeading == null`. После загрузки дерева логика не меняется: `activeCategoryLabel` или `'Каталог'`.
- Для подкатегории клиент берёт `label` последнего узла пути (`:757`). Если он отличается от `name` в дереве, текст сменится после загрузки — это допустимо, ошибки гидратации не будет: первый клиентский рендер совпадает с серверным.

```bash
for u in home cart catalog "catalog?category=<slug из локального дерева>" "catalog?is_new=true" "catalog?category=no-such-slug"; do
  h=$(curl -s "http://localhost:3000/$u")
  n=$(printf '%s' "$h" | grep -o '<h1' | wc -l)
  t=$(printf '%s' "$h" | tr '\n' ' ' | grep -o '<h1[^>]*>.*</h1>' | head -1 | sed 's/<[^>]*>//g')
  echo "$n [$t] /$u"
done
```

Ожидается: везде `1` и непустой текст — «OPTISPORT — спортивные товары оптом», «Ваша корзина», «Каталог», название категории, «Каталог», «Каталог».
