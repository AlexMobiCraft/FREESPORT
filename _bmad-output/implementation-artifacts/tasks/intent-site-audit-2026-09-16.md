## 0. Триггер

**Problem statement.** После выката 41.10–41.16 общая оценка выросла с 15 до 21, критичных замечаний больше нет (8 → 0). Но SEO-готовность осталась низкой: 35/100, провалены 4 из 15 проверок. Главная причина не в категориях: их починила 41.13, и в дублях они больше не встречаются. Замечания дают четыре группы адресов, которые эпик сознательно оставил как есть:

1. фильтры-подборки `?is_new=true`, `?is_hit=true` и служебный `?focusSearch=true`;
2. варианты `/login?next=…`;
3. `noindex` на `/cart`, `/checkout` и на вариантах `/login`;
4. шаблон description категорий, который владелец 14.09 утвердил длиннее 160 символов.

Кроме того, собственная правка эпика (E10 стори 41.16) внесла новое срабатывание 168-ФЗ `example`. Проверка вокруг отчёта выявила ещё три дефекта, которые сканер не называет, см. §5.

**Тип изменения.** В основном *Accepted-exception review*: исключения, принятые ради соответствия закону, а не зелёному отчёту, теперь составляют почти весь остаток. Владельцу нужно пересмотреть часть из них. По `example` — *Regression introduced by fix*.

## 2. Как устроен обход сканера (дополнение к §2 intent 10.09)

Прежние выводы подтвердились: сканер ходит анонимом с пустой корзиной, robots.txt не соблюдает, лимит 30 URL, варианты с параметрами считает разными страницами. Новое:

| Факт | Доказательство |
|---|---|
| Фрагмент адреса `#…` сканер отдельной страницей не считает (по косвенным признакам) | В обходе нет ни одного адреса с `#`, хотя в подвале есть `/partners#returns` (стори 41.12). В обход попал `/partners`, а `/partners#returns` — нет |
| `noindex` засчитывается как провал, даже если адрес закрыт в robots.txt | `/cart`, `/checkout`, `/login` стоят в `Disallow` (прод 16.09), при этом все шесть адресов с `noindex` попали в замечание |
| Один адрес `/login?next=…` даёт до пяти замечаний сразу | Дубль title, дубль description, canonical, noindex, «согласие только текстом». Четыре варианта — 17 строк отчёта |

## 6. Кандидаты изменений

Номера CC — рабочие. Нарезку на стори и FR делает `sprint-change-proposal-2026-09-16.md`.

- **CC-1. SEO подборок и длина description категорий.** Собственные title, description и canonical для `?is_new=true`, `?is_hit=true`, `?is_sale=true` — только если это единственный параметр. Добавить их в sitemap. Шаблон description категорий уложить в 160 символов для всех 85 узлов. Основа — механизм 41.13 (`catalog/page.tsx` + `generateMetadata`); сигнатуру `buildMetadata` не менять (HIGH).
- **CC-2. Поиск из шапки без query-параметра.** Три ссылки `Header.tsx` на `/catalog?focusSearch=true` заменить адресом без отдельного URL (например, `/catalog#search`), сохранив автофокус (`CatalogPageClient.tsx:1266-1273`).
- **CC-3. Меньше вариантов `/login?next` в обходе гостя.** Источники: `Header.tsx:131, 165, 249, 274, 308` (`/profile`, `/profile/favorites` → 307 в `middleware.ts`), `Footer.tsx:50`, `CheckoutStateView.tsx:11`. Нужен способ сохранить возврат после входа без уникального URL для каждой точки входа. Варианты — в D3.
- **CC-4. Один механизм исключения из индекса.** Для адресов, закрытых `Disallow`, решить: meta `noindex` или `Disallow` (D4).
- **CC-5. Формулировка согласия на рассылку.** «Я даю согласие на получение…» во всех трёх формах; новые версии текстов в реестре согласий (41.9/41.11); журнал старых версий не трогать.
- **CC-6 (опционально). `expireTime` в `next.config.ts`** — закрывает `tech-debt.md` п. 29, если стори всё равно пересобирает frontend.
- **CC-7. Редакторские хвосты.** Убрать `example`-плейсхолдеры из публичных форм (подпись у полей есть). Дополнить реестр 41.16: исправить основание E03, добавить `Edition` и `example`.
- **CC-8. Гигиена публичной поверхности (F1–F2).** Демо-маршруты — 404 на проде. Собственные metadata и `noindex` для `/register`, `/b2b-register`. Корневое умолчание — без латиницы и без «ведущая».
