# Задача: `size_value` не вмещает данные 1С (AC7 стори гонки cleanup)

Собрано 2026-08-27. Ветка `develop`, коммит `a167fb7b`. Все цифры — замеры на проде
`optisport.ru`, не рассуждение.

---

## 1. Симптом

12 вариантов в окне `offers` 17:20–17:24 25.08.2026 **не сохранились вообще**:

```
Error processing variant from offer / Error saving variant
DataError: value too long for type character varying(50)
```

Вариант не «обрезался» — запись не создалась. Это потеря данных, а не косметика.

Поле — единственное `varchar(50)` у `ProductVariant`:

```python
# backend/apps/products/models.py:854
size_value = cast(str, models.CharField("Размер", max_length=50, blank=True, db_index=True, ...))
```

`max_length=50` задаёт колонку `character varying(50)` в PostgreSQL (жёсткое
ограничение БД, считаются символы, не байты) и вешает `MaxLengthValidator`. Импорт
пишет варианты напрямую, минуя валидацию, поэтому ошибку возвращает база.

## 2. Что показал замер — читать до выбора решения

**Распределение длин `size_value` на проде (16 619 вариантов):**

| Длина | Вариантов |
|---|---|
| 0 (пусто) | 8 361 |
| 1–10 | 7 508 |
| 11–20 | 674 |
| 21–30 | 46 |
| 31–40 | 21 |
| 41–50 | 9 |

**Типичные значения** (то, чем поле должно быть): `M` × 476, `S` × 467, `L` × 455,
`XL` × 380, `XS` × 354, `XXL` × 130, `36`, `38`, `42`, `44`.

**Самые длинные значения** (то, чем поле стало):

```
49  Romana 501.96.00 Оборудование спортивное (черный)
49  Romana 501.35.01 Спортивное оборудование (черный)
47  2 мата-основы + 11 матов различных конфигураций
45  сборка и расстановка до готовности на объекте
45  трос металлический 17м + 2 талрепа + 2 зажима
43  в комплекте с закладными стаканами и сеткой

40  защитный мат 10*50 см ППЭ-ППУ, чехол ПВХ
38  flip, remi, willy, fanny, slidex, roxy
```

**Это не размеры.** Это комплектация, состав ткани, наименование услуги, список
моделей. Ни одно из них не является значением, по которому покупатель выбирает
товар. Расширение колонки сохранит их целиком — то есть аккуратно положит мусор
в поле размера, в индекс и в составное ограничение уникальности.

## 3. Откуда значение берётся

Два источника, оба в `backend/apps/products/services/variant_import.py`:

**Основной — `parse_characteristics` (стр. 135–172).** Берёт значение характеристики
1С, чьё имя попало в `size_names = {"размер", "size", "размерtd"}` либо начинается
с `размер_`. Фильтрует только булевы значения (`да`/`нет`/`-`). Длину не проверяет.
Если в реквизите «Размер» карточки 1С лежит текст комплектации — он и приезжает.

**Резервный — `extract_size_from_name` (стр. 175–194).** Вызывается на стр. 781–782,
когда характеристики размера нет: берёт содержимое **последних скобок** в
наименовании товара регуляркой `\(([^()]*(?:\([^()]*\)[^()]*)*)\)\s*$`. Длину тоже
не проверяет.

Запись — стр. 788–790 (`variant.size_value = ...`), сохранение батчами без
`full_clean()`.

## 4. Развилка

Решение принимает Alex, не исполнитель. Подготовь оба варианта с цифрами.

**А. Расширить колонку** (`max_length=255` либо `TextField`).
Плюс: ни одна запись не теряется, миграция расширения varchar в PostgreSQL ≥ 9.2
не переписывает таблицу и идёт мгновенно.
Минус: мусор сохраняется навсегда; `db_index=True` (стр. 1099) и составное
ограничение `(color_name, size_value)` (стр. 1103) начинают индексировать длинные
строки; фильтры каталога по размеру получают значения, которые никто не выберет.

**Б. Нормализовать на входе.** Отбрасывать значение, не похожее на размер, и/или
усекать с предупреждением в лог и в отчёт сессии.
Плюс: поле остаётся тем, чем задумано.
Минус: нужен критерий «похоже на размер», а он не бесплатный — см. ниже.

**В. Считать источником проблемы 1С.** Реквизит «Размер» в этих карточках заполнен
не размером. Правильное место починки — выгрузка, а не приёмник.
Замер выше говорит в пользу этого варианта: 9 записей из 16 619 — это не «длинные
размеры», это чужие данные в чужом поле.

Рекомендация: **Б как защита приёмника + В как разговор с 1С**. А в чистом виде не
решает задачу, он её прячет. Но выбор за Alex — вынеси развилку явно, не решай молча.

**Если выбран Б, критерий обязан быть консервативным.** Настоящие размеры в этом
каталоге — до 20 символов (674 записи в 11–20 включают `36-38`, `А5 (2XL)` и подобное).
Не выдумывай регулярку «настоящего размера»: любое значение длиннее порога —
подозрительное, но решение о пороге принимается по замеру, а не по интуиции.
Перед правкой пересними распределение — данные могли измениться.

## 5. Контракт приёмки

- [ ] Вариант с размером длиннее лимита **сохраняется**: либо целиком (А), либо с
      осознанным усечением/отбрасыванием и предупреждением в лог и в отчёт сессии (Б).
      `DataError` не возникает ни при каком входе.
- [ ] Решение зафиксировано: миграцией схемы (А) либо явной нормализацией с тестом (Б).
- [ ] Если выбран Б и значение отброшено/усечено — это видно в `report` сессии,
      а не только в логах воркера.
- [ ] Тест **падает до правки**. Прогнать и показать RED, иначе тест ничего не ловит.
- [ ] 12 вариантов, потерянных 25.08, доезжают на следующей полной выгрузке.

## 6. Ограничения проекта — читать до первой команды

- **Тесты только через Docker с PostgreSQL.** Локальный SQLite не годится: тут
  проверяется ограничение самой БД.
  ```bash
  cd docker && docker compose -p freesport-test -f docker-compose.test.yml run --rm -T backend \
    pytest -xvs apps/products/tests/<файл>
  ```
  `--env-file` тестовому compose не передаётся; `run --rm`, не `exec`.
  **Параллельные прогоны по одному проекту невозможны** — одна БД на проект,
  две сессии дерутся на `TRUNCATE` и дают лавину ложных падений.
- **Синтетические XML для тестов импорта 1С запрещены.** Только реальные файлы из
  `data/import_1c/` (каталог под широким правилом `.gitignore`, новые файлы — через
  `git add -f`). Срез реальной выгрузки уже закоммичен в
  `backend/tests/fixtures/1c-data/`.
- **GitNexus обязателен.** До правки `parse_characteristics`, `extract_size_from_name`
  и любого другого символа — `npx gitnexus impact <symbol> --direction upstream`,
  сообщить blast radius. Перед коммитом — `npx gitnexus detect-changes --scope all`.
  MCP-инструменты `gitnexus_*` отключены, только CLI.
- **Миграция** — если выбран вариант А. Прогнать на PostgreSQL в Docker, не на SQLite.
- **Деплой на прод ручной**, CI-шаг всегда skipped. После пересборки backend
  **обязателен `restart nginx`**, иначе весь внешний API уходит в 502.

## 7. Как проверить на проде после выката

```sql
-- новых потерь нет
SELECT count(*) FROM import_sessions
WHERE created_at > '<начало выгрузки>' AND error_message LIKE '%value too long%';

-- распределение длин не деградировало
SELECT max(length(size_value)), count(*) FILTER (WHERE length(size_value) > 20)
FROM product_variants;
```

Плюс в логах celery за окно выгрузки не должно быть `Error saving variant`.
