**Источник:** полный обход сайта 01.10.2026 — `tmp/audit-2026-09-28-full-site-check-2026-10-01.md`, находка Б1. Ранбук — `docs/integrations/1c/import-process.md`, раздел «Ранбук разовой очистки прода». Код — PR #268 (`spec-1c-deletion-marked-goods.md`).
**Проверено:** прод 01.10.2026 ~18:00 UTC. На сервере `b102b061`, туда входит PR #268. Контейнеры celery перезапущены в 16:41 UTC.
**Исполнитель:** разработчик с SSH-доступом к проду (навыки `production-database`, `production-server-ssh`). Тип — операция на проде, кода не требует.
**Решения владельца:** запуск полной выгрузки в 1С (шаг 3) и окно для удаления (шаг 5).
**Вне задачи:** фильтр публичного API по `category__is_active` (`deferred-work.md`). SEO-поля карточек, бренды на `/home` и прочие находки обхода. Бренды, атрибуты и файлы картинок команда не удаляет, и это так задумано.

## Проблема

PR #268 научил импорт не пускать на сайт товары вне ветки «СПОРТ» и помеченные на удаление. Но товары, загруженные **до** релиза, остались на месте: дельта-обмен их не присылает, поэтому не скрывает, а удаляет их только команда `purge_products_outside_root`. Её на проде не запускали.

Состояние прода на 01.10.2026:

- 1216 из 3244 опубликованных товаров лежат в неактивных категориях. Все они есть в `sitemap.xml` и открываются по прямой ссылке.
- Из них 1033 — вне дерева «СПОРТ»: заглушки `Категория <uuid>` (377), `onec-unresolved-category` (301), «Выбыло из ассортимента» (261), «Номенклатура к удалению» (89). Среди них имущество и услуги компании: ноутбуки, 12 планшетов, принтеры, «Аванс», «Монтаж / Погрузка / Доставка Падел корта».
- `SELECT count(*) FROM products WHERE onec_deleted` → 0, реестр `products_onec_excluded_items` пуст.

Правило допуска на проде работает. С 16:02 UTC прошло 93 сессии, из них 31 goods. Строки «Вне СПОРТ / к удалению» нет ни в одной, но это ожидаемо: в цикле обмена идёт один допущенный товар (Медбол ESPADO), а сессия, никого не исключившая, строку не пишет.

```sql
  SELECT id FROM categories WHERE name = 'СПОРТ' AND parent_id IS NULL
  UNION ALL
  SELECT c.id FROM categories c JOIN tree t ON c.parent_id = t.id
)

FROM products p JOIN categories c ON c.id = p.category_id
WHERE p.is_active GROUP BY 1, 2 ORDER BY 1, 2;
```

## Почему порядок обязателен

Нельзя сразу запускать `purge … --apply`. Команда удаляет **все** товары, чья категория в БД вне дерева. Среди 1033 товаров в заглушках и в `onec-unresolved-category` есть настоящие товары «СПОРТ»: при старых импортах их группа 1С не разрешилась. Полный прогон переносит допущенные товары в категорию их группы (`recategorized_products`). Без него `purge` удалит их вместе с мусором.

И наоборот: часть товаров, помеченных в 1С или перенесённых в «Номенклатуру к удалению», числится в БД в категориях «СПОРТ». Оценка — около 570: сейчас в дереве 2 420 товаров, после очистки ранбук ждёт ~1 850. Их скрывает только полный прогон, а `purge`, глядя на категорию в БД, их не тронет.

### 3. Полный прогон по свежей выгрузке

**Владелец запускает в 1С полную выгрузку каталога** через штатный обмен. Каждый её `goods_N.xml` приходит отдельной сессией, и правило допуска применяется так же, как в команде `import_products_from_1c --file-type=all` из ранбука. Поддерево «СПОРТ» сессия без `groups.xml` строит из БД.

Не прогонять команду по снимку 21.09 (`data/import_1c/`, `/home/freesport/goods_snapshots`). `--file-type=all` по снимку десятидневной давности откатит цены, остатки и карточки, изменённые в 1С после 21.09. Ручной прогон допустим только по файлам **этой же** свежей выгрузки, перехваченным watcher'ом (см. память «1C offers without images»). Флаги: `--data-dir <каталог перехвата> --file-type=all --keep-files`, без `--clear-existing`.

Как понять, что выгрузка прошла целиком:

- в `import_sessions` появились goods-сессии, и сумма `products_updated` по ним близка к числу товаров в 1С (по снимку 21.09 — около 9 900);
- в отчётах сессий есть строки `Вне СПОРТ / к удалению: …`; в `report_details` — счётчики `hidden_products`, `recategorized_products`;
- `SELECT count(*) FROM products WHERE onec_deleted` выросло с 0 до тысяч;
- новых goods-сессий нет 30 минут.

Ожидание: товары в дереве «СПОРТ» стремятся к ~1 850; `recategorized_products` > 0 (товары, вытащенные из заглушек). Если `hidden_products` затронул заметную долю из 2 021 активного товара в активных категориях «СПОРТ» без пометки в 1С — стоп, разбираться по построчному `INFO` в логе `import_products`.

## Откат

Порог: товаров «СПОРТ» заметно меньше эталона, удалены товары с заказами или сайт ломается.

```bash
cd /home/freesport/freesport
docker compose --env-file .env.prod -f docker/docker-compose.prod.yml stop backend celery celery-beat
docker compose --env-file .env.prod -f docker/docker-compose.prod.yml exec -T db \
  pg_restore -U postgres -d freesport --clean --if-exists < data/prod/backups/before_purge_<метка>.dump

```

После восстановления nginx может держать старый IP backend → `restart nginx` (память «Prod nginx upstream DNS»). Если ошибся сам импорт, а не очистка, дополнительно откатить релиз: `gh workflow run deploy.yml -f image_tag=<sha прошлого релиза>`.
