Собрано 2026-09-09. Ветка `develop`, коммит `792ce210`. Продолжение закрытой стори 41.8
(FR-41-19), которая разорвала стыки «бейдж → бренд → название» и оставила остальные.

## 1. Симптом

`element.textContent` собирает соседние DOM-узлы без пробела. На проде
`https://optisport.ru/catalog`, `document.querySelector('[role="article"]').textContent`:

```
Made In Russia Балетки для танцев белые350 ₽В корзину
              ↑ разорвано 41.8        ↑ склейка  ↑ склейка
```

**Объём задачи** (решения владельца от 2026-09-09, подробности в §8): девять стыков закрываются
одной стори; стык «кнопка → кнопка» исключён; `RecommendationsRow` не трогать; `-NaN%` в бейдже
скидки берётся прицепом.

Так карточку читают парсеры каталога и сканеры доступности. **Скринридера это не касается** —
проверено в стори 41.8 замерами Chromium AX tree и Windows UIA: узлы там раздельные и без
разделителей. Не заявлять улучшение произношения как цель, иначе повторится спор, который
в 41.8 длился шесть итераций ревью.

## 3. Механизм исправления — уже готов, писать новый не нужно

`frontend/src/components/common/TextSeparator.tsx`:

```tsx
export const TextSeparator: React.FC = () => <span className="sr-only left-0 top-0"> </span>;
```

**Три правила, каждое оплачено дефектом в 41.8 — не «упрощать»:**

1. **`left-0 top-0` не убирать.** `sr-only` даёт `position: absolute`, но не координаты, поэтому элемент
   встаёт в статическую позицию. В горизонтальной ленте `/electric` разделитель последней карточки
   оказывался на x≈1532 при окне 1440 и добавлял горизонтальную полосу прокрутки
   (`document.body.scrollWidth` 1533 против 1440). Фикс — коммит `c7017a7f`.
2. **Не заменять на пробел в потоке.** Контейнеры описания — flex-колонки (`p-3 flex flex-col` в compact,
   `p-4 flex flex-col` в grid). Голый `<span> </span>` станет flex-элементом и добавит строку
   высотой line-height — вёрстка поедет.
3. **Разделитель живёт внутри того же условия, что и узел, который он отделяет.** Иначе при отсутствующей
   скидке, РРЦ или кнопке останется висячий узел. В 41.8 это AC3, и проверяется оно тестами через
   `previousElementSibling`, а не только по количеству разделителей.

Обоснование «внешний вид не изменился» формулировать точно: гарантия — вынос из потока, размер 1×1
и `clip`, **а не** «margin не добавляет». `sr-only` в Tailwind v4 задаёт `margin: -1px` (проверено
в `node_modules/tailwindcss/dist`); неверная формулировка была отдельной находкой ревью.

## 7. Грабли проверки — стоили 41.8 отдельных итераций ревью

- **Копированием выделения не проверять.** `Ctrl+C` / `getSelection().toString()` разделяет слова
  и на непропатченном коде — браузер сам вставляет перевод строки на границах блочных элементов.
  Gate даёт ложное «дефекта нет». Единственный честный способ — `element.textContent`.
- **`curl` карточек не покажет.** Они рендерятся на клиенте: в HTML `/catalog` (30 260 байт)
  `role="article"` встречается 0 раз. Проверка только в браузере.
- **Тестом раскладка не проверяется.** В `frontend/vitest.config.mts` стоят `happy-dom` и `css: false`,
  `sr-only` в тестах ничего не скрывает. «Внешний вид не изменился» доказывается только осмотром
  в браузере или попиксельным A/B.
- **A/B делать на одном стенде и одной БД.** Сравнение «прод против локального» в 41.8 было отклонено
  ревью: составы каталогов разные, сравнивались разные товары. Рабочая схема — откатить фронт-файлы
  на baseline, снять, вернуть, снять снова. И замерить собственный шум метода: два прогона одного
  и того же кода расходились до 3.04% площади, то есть без замера шума любой мелкий дифф ничего не значит.
- **Docker bind-mount на Windows не пробрасывает file-watch.** После отката файлов обязательны
  `restart frontend` и `restart nginx`, иначе замеряется старая сборка.

## 8. Объём: решения владельца приняты 2026-09-09

1. **Все стыки закрываются одной стори** — не по одному за заход.
2. **`В КОРЗИНУ` → `ИЗБРАННОЕ` в объём НЕ входит:** разделитель между подписями двух контролов неуместен.
3. **`RecommendationsRow` не трогать** — ни чинить, ни удалять. Компонент мёртвый, но остаётся как есть.
4. **`-NaN%` берётся прицепом** — см. §8.3.

### 8.1. Что входит — девять стыков

### 8.3. Прицепом: `-NaN%` в бейдже скидки

**Дефект живой на проде, а не гипотетический.** Замер БД 2026-09-09:

```sql
SELECT is_sale, (discount_percent IS NULL) AS pct_null, count(*) FROM products GROUP BY 1,2;
 f | t | 9861
 t | t |   10
```

`discount_percent` пуст у **всех** 9 871 товаров, а `is_sale=true` — у 10 активных
(id 1292, 1311, 1322, 1334, 1336, 1348, 1356, 1688, 1689, 1696). Значит бейдж скидки на
`/electric` **никогда** не показывает процент корректно — всегда `-NaN%`.

Механизм: call sites ставят `badge` и `oldPrice` по разным условиям.

```tsx
// app/(electric)/electric/catalog/page.tsx:585-588 — badge по одному лишь is_sale
if (product.is_sale) badge = 'sale';
// :605-609 — oldPrice требует ещё и discount_percent
oldPrice={product.is_sale && product.discount_percent ? Math.round(...) : undefined}
```

В `ElectricProductCard.tsx:101-109` в выражение `((oldPrice! - price) / oldPrice!)` попадает
`undefined`; non-null assertion влияет только на TypeScript, не на runtime. То же расхождение —
в `components/home/ElectricProductSection.tsx:272-277` и `components/home/HitsSection.tsx:322-328`.

Воспроизведено прогоном 2026-09-09:

```
render(<ElectricProductCard badge="sale" price={1000} /* без oldPrice */ ... />)
→ "-NaN% ♡Made In Russia Балетки1 000 ₽В КОРЗИНУИЗБРАННОЕ"
```

Исправление: показывать процент только при конечном `oldPrice > price`, иначе безопасный
текст («Акция»). Обе ветки покрыть тестом — сегодня зелёный тест на `-NaN%` отсутствует,
потому что случай не тестировался вовсе.
