## А. Карточки товаров

### А1. Служебная пометка в описании самбовок BB300 — данные, не код

**Факт.** У товара `/product/sambovki-boybo-naturzamsha-kombinirovannye-bb300-sine-krasnyj` («Самбовки BoyBo натур.замша комбинированные (BB300), сине-красный») всё описание — «габариты по разерам не исправлены». Текст попадает в видимое описание, `meta description`, `og:description` и JSON-LD. Других служебных пометок среди 1657 карточек не найдено.

**Откуда.** Тег `<Описание>` товара в `goods.xml` (`backend/apps/products/services/parser.py:290`). Импорт обновляет описание, только если оно в 1С **непустое** и отличается от текущего (`variant_import.py:1178-1181`).

**Что сделать (владелец или контент-менеджер):**
- Основной путь: заменить описание в карточке номенклатуры 1С нормальным текстом. После ближайшего обмена с этим товаром оно придёт на сайт.
- Если описание в 1С просто очистить, на сайте старый текст **останется**: пустое значение импорт не переносит. Тогда очистить поле «Описание» и в админке Django (Товары → поиск по «BB300»).

**Приёмка:** в серверном HTML карточки нет строки «не исправлены».

### А2. «- Без ТМ» в заголовке карточки

Список держать в одном месте: в `deferred-work.md` уже записано, что подобные списки технических значений расходятся между модулями.

### А3. HTML-теги в описании товара

**Факт.** В 21 описании из 1С есть `<br>` (всего 46 тегов). Описание выводится как обычный текст:
- `meta description` и `og:description` — `product.description.substring(0, 160)` и полное описание без обрезки (`page.tsx:38-39`);
- видимый блок «Описание» — `{product.description}` в `<p>` (`ProductSummary.tsx:472-476`): React экранирует строку, и покупатель видит буквальный «<br>»;
- JSON-LD — `description: product.description`.

Пример: `/product/kovrik-dlja-jogi-espado-nbr-1836110-sm-zelenyj-es2123-110`. Кроме того, в описаниях бывают переводы строк `\n` (например, `/product/cheshki-baletki-s-setkoj-chernye`), а `<p>` их схлопывает.

**Правки:**
- В `utils/htmlContent.ts` (рядом с `extractBodyContent`) — функция перевода описания в простой текст. `<br>`, `<br/>`, `<br />`, `</p>` → перевод строки; остальные теги удалить; декодировать `&amp; &lt; &gt; &quot; &#39; &nbsp;`.
- Видимое описание: результат этой функции в элементе с `whitespace-pre-line`. Вставлять HTML через `dangerouslySetInnerHTML` **нельзя**: описание приходит из 1С без санитайзера.
- `meta description`, `og:description`, JSON-LD — тот же простой текст, пробельные символы схлопнуты в один пробел. Для `meta` и `og` — обрезка до 160 символов по границе слова, без разрыва слова посередине.
- Пустой результат — `description` не выводить (как сейчас при пустом описании).
- Бэкенд и импорт 1С не трогать: текст в БД остаётся как есть.

**Тесты:** функция — `<br>` во всех трёх написаниях, вложенные теги, сущности, `\n`, пустая строка, строка только из тегов; `generateMetadata` — description без `<` и не длиннее 160; `ProductSummary` — нет буквального «<br>», есть перевод строки.

## В. Вёрстка контента блога и новостей

**Решение владельца 02.10.2026:** контент статей и новостей — HTML-фрагмент из смысловых тегов без собственных стилей; оформление даёт сайт. Markdown и визуальный редактор отклонены. Готовые фрагменты для замены через админку — `tmp/blog-news-content-2026-10-02/` (вне git). Владелец заменяет контент **после** релиза В1: без него вставленный фрагмент покажется без оформления.

**Факт.**
- Контент выводится как есть через `dangerouslySetInnerHTML` с классами `prose prose-lg` (`blog/[slug]/page.tsx:128-131`, `news/[slug]/page.tsx:119-122`). Плагина `@tailwindcss/typography` в проекте нет, поэтому `prose` ничего не делает. Preflight Tailwind 4 обнуляет отступы абзацев, размеры `h2`/`h3` и маркеры списков. Поэтому авторы вставили в статьи целый HTML-документ с `<style>` (глобальные `body`, `h1`, `p`). Отсюда на странице два `<!DOCTYPE>`, два `<title>` и два H1, а шрифт всей страницы меняется на Arial.
- Новости сохранены в Markdown (`# **…**`, `###`, `**`, `* `), но Markdown нигде не рендерится. Подсказка поля в модели — «HTML или Markdown» (`common/models.py`, поле `content` у `News` и `BlogPost`).
- CMS-страницы уже решают ту же задачу набором arbitrary-вариантов (`app/(blue)/[slug]/page.tsx:105`) и чисткой при сохранении (`pages/models.py:13-16`, `130-160`).

### В1. Стили контента

- Вынести набор классов из `[slug]/page.tsx:105` в общую константу (например, `utils/richContent.ts`) и дополнить: отступ сверху у `h2`/`h3`, `blockquote` (отступ слева, рамка, приглушённый цвет), `img` (`max-w-full h-auto rounded`), `hr`, `strong`.
- Применить её в `blog/[slug]` и `news/[slug]` вместо `prose prose-lg`; в `[slug]` — заменить локальную строку константой. `privacy-policy/page.tsx:127` тоже держит неработающий `prose prose-neutral` — сначала сравнить вид политики до и после, юридическую страницу менять только при совпадении вида.

### В2. Очистка контента при сохранении (бэкенд)

- `BlogPost.save()` и `News.save()`: вырезать `<style>`, `<script>`, `<head>` с содержимым (переиспользовать `_STRIP_BLOCKS_RE` из `pages/models.py`, вынеся его в общий модуль). Затем `bleach.clean` по белому списку: `p, br, h2, h3, h4, ul, ol, li, strong, b, em, i, a[href,title,target,rel], blockquote, img[src,alt,width,height], figure, figcaption, table, thead, tbody, tr, th, td, hr`; `strip=True`. Атрибуты `style` и `class` не пропускать.
- `<h1>` в контенте до `bleach` превращать в `<h2>`: H1 страницы выводит шаблон из поля «Заголовок».
- Подсказку поля `content` заменить на «HTML-фрагмент: абзацы, подзаголовки h2/h3, списки, ссылки. Без <html>, <style> и заголовка статьи». Это изменение `help_text` даёт миграцию — её создать.
- Существующие записи данными не мигрировать: владелец заменит их через админку, очистка сработает при сохранении.

### В3. SEO-поля статьи — только простой текст

`BlogPost.meta_description` на проде: у одной статьи — буквальный тег `<meta name="description" content="…">`, у двух — 217 и 225 символов, с пустой строкой внутри. При сохранении удалять теги, схлопывать пробелы и переводы строк. В форме админки показывать предупреждение, если `meta_description` длиннее 160 символов, а `meta_title` — длиннее 50: к нему дописывается « | Статьи OPTISPORT», 19 символов.

**Тесты бэкенда** (`apps/common/tests/`, запуск через Docker, навык `docker-test-run`): документ с `<!DOCTYPE>`, `<head>`, `<style>`, `<h1>` → сохраняется фрагмент без них, `<h1>` стал `<h2>`, CSS не проступил текстом; `style`/`class` срезаны; `<script>` удалён; `meta_description` с тегом и переводами строк → простой текст.
