# Этапы заказа из 1С на сайт: настройка выгрузки заказов БУС

Регламент для администратора 1С. После него клиент видит в кабинете, на странице заказа и в PDF этапы
«В обработке» → «Передан на склад» → «Отправлен» → «Доставлен», а также отмену заказа в 1С.

Спека: `_bmad-output/implementation-artifacts/spec-1c-order-statuses-import.md`, исследование —
`research-1c-order-statuses.md` там же.

## Как это работает

1. В настройке обмена «По расписанию» (настройка Б из [регламента загрузки заказов](./orders-pull-schedule-setup.md))
   включается выгрузка заказов «только изменения».
2. БУС раз в 5 минут кладёт изменённые заказы в архив `v8_*.zip` и отправляет его на сайт:
   `type=sale&mode=file`, затем `type=sale&mode=import&filename=orders_<n>_<uuid>.xml`.
3. Сайт читает все `orders*.xml` этого обмена, находит субзаказ по `<Номер>` и `<Ид>` (`order-<pk>`),
   ставит статус по реквизиту «Статуса заказа ИД» и пересчитывает статус мастер-заказа.
   Импорт каталога при этом не запускается.

Этап берётся из **состояния заказа**, которое УТ вычисляет сама по резервам, отгрузкам и оплатам.
Менеджеру ничего вручную переключать не нужно.

Оплату из 1С сайт **не принимает**: даты оплаты и отгрузки, документы оплат и отгрузок игнорируются.

## Шаг 1. Выгрузка заказов в настройке Б

Карточка настройки Б → кнопка «Настроить» у блока синхронизации заказов (форма «Настройка обмена документами») →
блок «Настройка выгрузки документов»:

| Параметр | Значение |
| --- | --- |
| Выгружать заказы | Да |
| Выгружаются с | дата включения регламента (старые заказы выгружать незачем) |
| Только изменения (общие параметры настройки Б) | Да — уже включено по регламенту загрузки заказов |
| Выгружать отмененные товары | **Нет** — см. «Отмена заказа» ниже |
| Выгружать офлайн заказы | Нет — заказы, заведённые в самой 1С, сайту не нужны |
| Выгружать оплаты, Выгружать отгрузки | Нет |

Настройку А («В режиме реального времени») не трогайте: «Выгружать заказы» там остаётся выключенным.

## Шаг 2. Соответствия статусов

«Настроить соответствия статусов заказов» → форма «Сопоставление статусов», вкладка «Заказы».

1. «Источник статусов заказов 1С» — **«Состояния заказов»**.
2. Нажмите **«Загрузить с сайта»** — колонка «Ид статуса» получит список статусов сайта (запрос `type=sale&mode=info`).
   В списке должен быть «Передан на склад». Его нет — на сайт не выкатан этот релиз, дальше не продолжайте.
3. Заполните таблицу:

| Состояние заказа в УТ | Ид статуса | Статус на сайте |
| --- | --- | --- |
| Ожидается согласование | На согласовании | Новый (`pending`) |
| Ожидается оплата до обеспечения | К выполнению | В обработке (`processing`) |
| Готов к обеспечению | К выполнению | В обработке (`processing`) |
| Ожидается оплата до отгрузки | К выполнению | В обработке (`processing`) |
| Ожидается обеспечение | К выполнению | В обработке (`processing`) |
| Готов к отгрузке | Передан на склад | Передан на склад (`at_warehouse`) |
| В процессе отгрузки | Передан на склад | Передан на склад (`at_warehouse`) |
| Ожидается оплата | Отгружен | Отправлен (`shipped`) |
| Готов к закрытию | Отгружен | Отправлен (`shipped`) |
| Закрыт | Закрыт | Доставлен (`delivered`) |

4. Поля **«Когда оплачен»**, **«Когда отгружен»**, **«Когда оплачен и отгружен»** оставьте **пустыми**.
   БУС проверяет их раньше таблицы: заполненное «Когда оплачен» с момента оплаты вытесняет этап, и
   «Передан на склад» сайт уже не увидит.
5. «Применить и закрыть».

Статусы сайта двигаются только вперёд: состояние, откатившееся в 1С назад (например, из «Готов к отгрузке»
в «Ожидается обеспечение»), не возвращает статус сайта, а только записывается в поле «Статус 1С» карточки
заказа в админке.

## Шаг 3. Номер заказа сайта

«Настроить реквизиты загружаемых в 1С документов» → «Заказ клиента»: строка **«Номер по данным клиента»** —
«Предопределенный алгоритм», значение **«Номер с сайта»** (значение БУС по умолчанию). Из этого реквизита БУС
пишет `<Номер>` при выгрузке; по нему и по `<Ид>` сайт находит заказ. Другое значение — и заказ не найдётся
или упадёт в конфликт номера.

## Отмена заказа

Сайт ставит «Отменён», если в документе реквизит `Отменен` = `true` и при этом:

- в документе нет строк товаров (строка доставки не в счёт) — все строки отменены в 1С, или
- заказ помечен на удаление.

Галка «Выгружать отмененные товары» должна быть **выключена**. Если её включить, БУС выгружает отменённые
строки и ставит `Отменен` = `true` любому заказу, где отменена хоть одна строка. Сайт такой отмене не верит:
пишет предупреждение в лог, статус берёт по таблице, но **в финальный статус не переводит**. Так «Закрыт»
у частично отменённого заказа не превращается в «Доставлен», а в «Статус 1С» записывается фактическое значение.

## Бонусы тренерам

Бонус начисляется, когда мастер-заказ переходит **ровно** в статус «Статус заказа для начисления» из настроек
бонусной программы (по умолчанию «Доставлен»). Заказ может перескочить промежуточный статус: например, из
«Передан на склад» сразу в «Доставлен», если между выгрузками заказ отгрузили и закрыли. Поэтому статусом
начисления держите «Доставлен», а не «Отправлен» или «Передан на склад».

## Проверка

1. В логе nginx прода раз в 5 минут, когда в 1С есть изменённые заказы, идут загрузки заказов:

   ```bash
   docker compose --env-file .env.prod -f docker/docker-compose.prod.yml logs nginx | grep "type=sale&mode=import&filename=orders"
   ```

   Ответ сайта на такой запрос — `success`. `failure` бывает, только если XML не дошёл, битый или старше
   суток, либо при сбое БД; тогда БУС оставляет пакет и повторяет его при следующем запуске.

2. В логе backend — строка с итогами по каждому файлу:

   ```bash
   docker compose --env-file .env.prod -f docker/docker-compose.prod.yml logs backend | grep "\[BUS ORDERS\]"
   ```

   `not_found` — заказы без пары на сайте (например, заведённые в 1С вручную), это штатно.
   `no_status` — у состояния заказа нет строки в таблице соответствий.

3. Копия каждого принятого файла лежит в каталоге журналов обмена (`EXCHANGE_LOG_DIR`, по умолчанию
   `backend/var/1c_exchange/logs/`).

4. Контрольный заказ: проведите заказ с сайта до «Готов к отгрузке» — в кабинете клиента он станет
   «Передан на склад» за один интервал обмена.

## Откат

В настройке Б снимите «Выгружать заказы». Статусы на сайте останутся последними полученными; новые этапы
перестанут приходить.

## Тестовые данные

Реальная выгрузка `orders_*.xml` с `test_base` кладётся в `backend/data/import_1c/orders/` и прогоняется
тестом `tests/integration/test_orders_bus_import.py::test_bus_orders_real_export` (`data_dependent`).
Снять её: на `test_base` провести 3–4 заказа с сайта до «Готов к отгрузке» и «Закрыт», один отменить,
в настройке «Обмен локальный» включить выгрузку заказов в каталог с источником «Состояния заказов» и
таблицей из шага 2, запустить обмен. В приватный репозиторий `FREESPORT-1c-test-data` (каталог `orders/`)
файл добавляется по команде владельца.
