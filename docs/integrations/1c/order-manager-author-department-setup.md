# Заказы сайта → 1С: Менеджер и Подразделение из карточки клиента

Регламент для администратора 1С. Настройка делается в 1С в настройке обмена БУС, без правок кода сайта и расширения БУС. Проверено на локальной базе `test_base` 10.11.2026.

## Зачем это нужно

Заказ клиента, который БУС загружает с сайта, по умолчанию получает Менеджера и Автора, равных пользователю сеанса обмена (`<Не указан>` у фонового задания), а Подразделение остаётся пустым. Менеджеры не могут работать с такими заказами: их не видно в «своих» отборах.

После настройки:

| Реквизит | Значение в загруженном заказе |
| --- | --- |
| Менеджер | «Основной менеджер» партнёра; если он не указан или недействителен — «Чернов В (Менеджер)» |
| Подразделение | подразделение этого менеджера; если оно не указано — «Отдел продаж» |
| Автор | **не меняется**: остаётся `<Не указан>` (см. «Ограничение: Автор») |

## К каким настройкам применять

К каждой настройке обмена БУС, у которой в блоке «Документы» стоит «Загружать заказы = Да». Для схемы из [регламента настройки «По расписанию»](./orders-pull-schedule-setup.md) это настройка Б; настройка А («В режиме реального времени») заказы не загружает, её не трогать.

## Как это работает

БУС заполняет реквизиты заказа по таблице соответствий **строго сверху вниз**:

1. «Менеджер» и «Подразделение» получают запасные значения — «Фиксированное значение»: «Чернов В (Менеджер)» и «Отдел продаж».
2. «Партнер» заполняет партнёра заказа.
3. Строка «Автор» с типом «<Свой алгоритм>» стоит **после** «Партнер», поэтому алгоритм видит партнёра. Он читает его «Основной менеджер» и, если менеджер действителен, записывает его в Менеджера и его подразделение — в Подразделение. Для уже существующего заказа алгоритм возвращает прежние Менеджера и Подразделение, поэтому ручная переназначка в 1С при повторной загрузке не затирается.

Алгоритм находится именно в строке «Автор», потому что это единственная строка, которую можно добавить в конец таблицы: «Менеджер» и «Подразделение» выполняются до того, как известен партнёр.

## Перед применением

1. Сохраните скриншот таблицы соответствий «Заказ клиента» (тип и значение строк «Менеджер», «Подразделение», есть ли строка «Автор»): это исходное состояние для отката.
2. Проверено на `test_base` с расширением БУС 8.1.0.40. На проде стоит 8.1.0.45: по разбору кода загрузки заказов (цикл по таблице соответствий и обработка «<Свой алгоритм>») эти места совпадают, но проверку из раздела «Проверка после включения» на проде выполните обязательно.
3. Решение владельца и результаты проверки — в [спеке](../../../_bmad-output/implementation-artifacts/spec-1c-order-manager-author-department.md).

## Шаги

> Значения ниже записаны в настройку на `test_base` программно и проверены загрузкой заказов. Названия кнопок и переключателей формы настройки перед работой сверьте на экране: порядок строк и сами значения важны, внешний вид формы нет.

1. Откройте настройку обмена БУС → документ «Заказ клиента» → форму заполнения реквизитов загружаемого документа. Включите **расширенный режим**: в «Базовых настройках» показаны только 7 реквизитов, строки «Автор» там нет.
2. Строка «Менеджер»: тип «Фиксированное значение», значение — пользователь «Чернов В (Менеджер)». Значение выбирайте в форме (из справочника «Пользователи»), не вписывайте текстом.
3. Строка «Подразделение»: тип «Фиксированное значение», значение — «Отдел продаж» (справочник «Структура предприятия»).
4. Строка «Автор» (если её нет, она появится в конце таблицы после «Партнер»): тип «<Свой алгоритм>», значение — текст ниже.
5. **Проверьте порядок строк:** «Автор» должна быть ниже «Партнер». Если выше — алгоритм не увидит партнёра и молча оставит запасного менеджера (Чернова).
6. Сохраните настройку. Остальные строки не меняйте.

Текст алгоритма (вставлять без изменений, отступы — табуляции):

```bsl
Если [Документ].ЭтоНовый() Тогда
	[Результат] = [Документ].Менеджер; // запасной менеджер = автор
	ОснМенеджер = [Документ].Партнер.ОсновнойМенеджер;
	Если ЗначениеЗаполнено(ОснМенеджер) И НЕ ОснМенеджер.Недействителен Тогда
		[Документ].Менеджер = ОснМенеджер;
		Если ЗначениеЗаполнено(ОснМенеджер.Подразделение) Тогда
			[Документ].Подразделение = ОснМенеджер.Подразделение;
		КонецЕсли;
	КонецЕсли;
Иначе
	[Документ].Менеджер = [Документ].Ссылка.Менеджер;
	[Документ].Подразделение = [Документ].Ссылка.Подразделение;
	[Результат] = [Документ].Ссылка.Автор;
КонецЕсли;
```

Требования к тексту:

- Поле должно сохранять переводы строк. В тексте есть комментарий `//`: если вставка склеит строки в одну, комментарий закомментирует весь остальной код, и менеджер не подставится.
- Строки с `[Результат]` оставлены как в проверенной версии: на реквизит «Автор» они сейчас не влияют (см. ниже). Если после обновления расширения БУС Автор начнёт заполняться, у нового заказа он станет «Чернов В (Менеджер)», у существующего — прежним; повторите проверку после каждого обновления расширения.

## Ограничение: Автор

Автор заказа остаётся `<Не указан>`. На `test_base` значение «Автор» проверено тремя способами — алгоритм из этого регламента, простой `[Результат] = [Документ].Менеджер;` и «Фиксированное значение» «Чернов В (Менеджер)». Во всех трёх случаях в загруженном заказе Автор — элемент `<Не указан>` (пользователь сеанса обмена). Где именно значение перезаписывается, не установлено; настройкой соответствий это не обходится. Решение владельца 10.11.2026: принять как есть. Если Автор понадобится, нужна отдельная задача на расширение БУС или разбор записи документа в самой 1С.

Остальные ограничения:

- **Уже загруженные заказы не дозаполняются** — менеджеры правят их вручную.
- **Недействительный основной менеджер** (`Недействителен = Истина`) считается отсутствующим: берётся «Чернов В (Менеджер)».
- Настройка не влияет на заказы, которые БУС уже создал; она действует на новые.
- **Запасной менеджер — конкретный пользователь.** Если «Чернов В (Менеджер)» станет недействителен, будет удалён или заменён, новые заказы без основного менеджера получат недействительного менеджера. Замените значение в строке «Менеджер» (и при необходимости «Подразделение») в каждой настройке, которая загружает заказы. Отвечает за это администратор 1С; проверять при кадровых изменениях.

## Проверка после включения

1. Оформите на сайте тестовый заказ клиентом, у которого в 1С указан «Основной менеджер».
2. Через ≈5 минут (расписание настройки Б — 300 с) найдите документ в 1С: номер вида `СМУТ-…`, номер сайта — в комментарии `[Номер документа на сайте: …]`.
3. Сверьтесь с таблицей:

| Сценарий | Менеджер | Подразделение |
| --- | --- | --- |
| Основной менеджер с подразделением | он сам | его подразделение |
| Основного менеджера нет | Чернов В (Менеджер) | Отдел продаж |
| Основной менеджер недействителен | Чернов В (Менеджер) | Отдел продаж |
| Основной менеджер без подразделения | он сам | Отдел продаж |
| Новый клиент, созданный БУС из заказа | Чернов В (Менеджер) | Отдел продаж |
| Повторная загрузка после ручной смены менеджера | не меняется | не меняется |

Журнал БУС (регистр «БУС_Логирование») не должен содержать ошибок «<Свой алгоритм>».

Результат проверки на `test_base` (10.11.2026): все строки таблицы выполнены, Автор — `<Не указан>` во всех заказах.

## Откат

Откройте ту же форму и верните строкам «Менеджер» и «Подразделение» исходные тип и значение (по скриншоту из раздела «Перед применением»; по умолчанию — «Предопределённый алгоритм»). В строке «Автор» очистите значение: БУС пропускает строки с пустым значением, поэтому алгоритм перестанет выполняться. Если строки «Автор» до настройки не было, пустая строка остаётся в таблице и ни на что не влияет. Уже загруженные заказы не меняются. После отката заказы снова получают Менеджера по умолчанию (пользователь сеанса обмена).
